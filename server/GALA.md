# GALA in the server

This is the single GALA ledger for the server: which twins exist, which compiler they were built with, what still blocks the rest of the cursor, and how to continue.
It does not restate construct substitutions or gap classification; those live in the project-independent translation reference at [`../.agents/skills/gala-from-go/SKILL.md`](../.agents/skills/gala-from-go/SKILL.md).
The loop that consumes both is [`../.agents/skills/gala-loop/SKILL.md`](../.agents/skills/gala-loop/SKILL.md), and verification is [`scripts/gala/verify.sh`](scripts/gala/verify.sh).

## Contract

Both halves of a twin are committed: the `.gala` source and the Go file the transpiler generates from it.
The Go build never invokes GALA, so a generated file without its source is unreadable to the next maintainer and a source without its generated file is not in the build at all.
Never hand-edit a generated file; it carries a `DO NOT EDIT` header and the next transpile discards the edit without a trace.
Transpile from the package directory so the emitted `//line` directives stay relative: `cd server/<pkg> && gala transpile --stdlib-module go.gala.fyi/stdlib -i <name>.gala -o <name>.go`.
The transpiler writes its analysis cache under `server/.gala/`, which is gitignored.
A stale cache entry that survives a `.gala` source replacement can misorder an unrelated twin's emitted imports, so delete `server/.gala/` when a regeneration flips unexpectedly rather than treating the flip as a real drift.

### Adopted runtime (decided 2026-10-10)

TASK-0353 decides that server twins adopt the published Go module `go.gala.fyi/stdlib` at the version paired with the pinned compiler, rather than staying runtime-free.
The scope is every existing twin plus new twins and cursor candidates: a twin moves to the runtime where the emitted Go keeps the package's Go-facing API and wire format unchanged, and keeps its current form where a runtime construct would change them — an exported `val` becoming `std.Immutable`, a sealed type's merged struct, non-`var` struct fields gaining wrappers, or `Codec` changing a wire shape.
`martianoff/gala` stays banned in generated Go, and the only allowed runtime import path is `go.gala.fyi/stdlib/...` from the module pinned in `server/go.mod`.
The decision rests on a scratch check on the pinned compiler (`cd2fdcb5`, 2026-10-10): a source using `val`, a GALA struct, an `opaque type`, a sealed type with a `match`, and `std.Try` transpiled with `--stdlib-module go.gala.fyi/stdlib` to Go importing only `go.gala.fyi/stdlib/std`, and that Go built and ran in a plain Go module requiring `go.gala.fyi/stdlib v0.87.1`, which has no transitive requirements.
A minimal Docker build mirroring `server/Dockerfile`'s `go mod download` and build stages fetched the module with an empty cache and ran the binary, and the isolated-stack shape (source mount plus a `GOMODCACHE` volume with `go run`) fetched it into the volume and ran.

The contract landed in TASK-0353.01 on 2026-10-10: `server/go.mod` and `server/go.sum` carry the `go.gala.fyi/stdlib v0.87.1` requirement, `verify.sh` transpiles every twin with `--stdlib-module go.gala.fyi/stdlib` and rejects only `martianoff/gala`, and [`server/tools.go`](tools.go) anchors the requirement under the `tools` build tag so `go mod tidy` is a no-op until a committed twin imports it.
The `gala-from-go` and `gala-loop` updates are TASK-0353.02, and the twin and cursor migration is TASK-0353.03.
TASK-0353.03 landed the migration on 2026-10-10: eighteen of the twenty-three committed twins now import `go.gala.fyi/stdlib`, and the five that stay runtime-free are recorded in the registry with the Go-facing name that forces their form.

### Twin style after the migration (TASK-0353.03, 2026-10-10)

A twin uses the runtime wherever the emitted Go keeps its Go-facing surface: internal bindings are `val` (or `var` when the address is taken or the value is reassigned), Go slices, maps, and builtins go through `go_interop`, and an `opaque type` or a result list whose body builds its results lowers through `std` where no Go caller observes the difference.
`var` is still the spelling for every name a Go caller, a handwritten sibling, or a test reads as a plain value: package-level names, struct fields, and any binding whose method set or address matters.
Migrating a name to `val` is a surface decision rather than a style preference, because a package-level `val` emits `var X = std.NewImmutable(...)` and every Go read then needs `.Get()`.

The boundary rules are unchanged from the runtime-free era: an exported `val` behind `std.Immutable`, a sealed type's merged struct, a non-`var` struct field behind `std.Immutable[T]`, and a `Codec` where a struct tag defined the wire shape all reshape the Go-facing surface.
A member whose construct would change that surface stays in a handwritten Go sibling in the same package, which the transpiler resolves without an import: a map literal, a slice expression, a `(T, bool)` type assertion, or an interface method with several results.
[GO_INTEROP.MD Part 3](https://github.com/martianoff/gala/blob/master/docs/GO_INTEROP.MD#part-3-one-package-two-languages) is the reference, and `middleware/auth_session.go`, `postgres/dailylogs_types.go`, and `discord_bot/interop.go` are the siblings that rule produced here.
A candidate whose Go-facing API cannot survive the split stays handwritten.

Read the emitted import block before committing a twin: a runtime import must be the `go.gala.fyi/stdlib/...` module pinned in `server/go.mod`, and `verify.sh` fails a twin whose generated Go imports `martianoff/gala`.
A runtime-free twin is not stale; `verify.sh` accepts either form and the registry names which is which.

### Runtime idiom pass (TASK-0354, 2026-10-10)

The committed twins' Go-spelled failure handling was rewritten with the runtime as values: a Go call returning `(T, error)` used as a value is already a `Try[T]` (the transpiler emits `std.GoTry`), `match` takes `Success`/`Failure` apart, `OnFailure`/`GetOrElse` handle the ends, `FromError` covers a void error return, and `go_interop.OptionFromMap` covers absence at a map boundary.
The pass touched `middleware/auth.gala`, `utils/request_utils.gala`, `routes/respondent_identity.gala`, `services/services.gala`, both `num_users.gala` and both `active_users.gala` twins, and `discord_bot/init.gala`; the generated Go keeps every Go-facing signature, every panic site's `logger.StdErr.Panicln` call, every HTTP status, and every wire payload, and no test changed.
`Try(...)` is the panic-catching constructor (`std.Try[T]{}.Apply` over a closure that panics on the error), so it was not used where the current code propagates a panic: the void call `bot.Open()` uses `FromError`, which checks the error without catching panics.
`routes/respondent_identity.gala`'s `liveUsers` lookup became `go_interop.OptionFromMap(liveUsers, lookupKey)` matched as `Some(liveUser) if liveUser != nil` against `case _`, which keeps the explicit-nil map value and the fallback branch as distinct as the comma-ok form did.

The sites that stay on the Go spelling, and why:

- Pointer nil guards stay in `routes/respondent_identity.gala` (`cloneUser`'s `user == nil`, `sanitizedResponseUser`'s `sanitized == nil`, `populateSignUpResponsePayloadIdentity`'s `response == nil`), `routes/users.gala` (`user == nil`), `routes/guest_response_ownership.gala` (`response == nil`), and `services/services.gala` (the `user` and `body` parameters), as TASK-0354 shipped them.
  When that pass ran, the adopted runtime had no pointer-to-Option conversion; `go_interop.OptionFromMap` was its only absence-to-Option helper, so rewriting a pointer guard would only have moved the same `== nil` test into a `Some`/`None` constructor without removing it.
  GALA 0.92.0 adds `std.OptionPtrOf`, which yields an `OptionPtr` that is empty for a nil `*T`, and the sealed view matches it as `Some`/`None`; a scratch transpile on rev `4bd2d4e8` emits `std.OptionPtrOf(user).MatchView()` and builds (verified 2026-10-21), so the rewrite is available and is tracked as TASK-0361 rather than done in this bump.
  `populateSignUpResponsePayloadIdentity` and `CallApi` are called by handwritten Go (`routes/event_routes.go`, `services/*`), and the route helpers are read by `routes/guest_response_ownership_test.go`, so those signatures cannot change in any case.
- `discord_bot/init.gala`'s `val botSession, err = discordgo.New(...)` stays Go-spelled because the original publishes the returned session to the package-level `bot` before the error check, and the value layer has no spelling that yields the session on `Failure`; `discordgo.New` on v0.27.1 always returns a non-nil session, so publish-then-check is the behavior being kept.
- Blank error discards stay blank (`json.Marshal` and `http.NewRequest` in `services.gala`, `bot.GuildChannels` in `init.gala`), because the original deliberately ignores those errors and no runtime spelling represents an ignored error.

The pass also found that the transpiler resolved a Go call's signature only when the import qualifier named the package itself: the `pgstore "timeful/server/postgres"` alias left `pgstore.DefaultRepository()` an unknown type, so the bot and command twins use `"timeful/server/postgres"` and spell it `postgres.DefaultRepository()`.
That alias defect is [#749](https://github.com/martianoff/gala/issues/749) and is fixed since the `014c2f23` lock (verified 2026-10-18: the aliased call now emits `std.GoTry`), so the package-name spelling stays a style choice rather than a requirement.
The same pass found that an unannotated `go_interop.OptionFromMap(...).ForEach` lambda leaked the compiler's own `T` when the map's value type was a GALA struct declared in another package, so `discord_bot/init.gala` annotates the lambda; that leak is [#750](https://github.com/martianoff/gala/issues/750) and is fixed since the `014c2f23` lock (verified 2026-10-18: the lambda now emits the concrete type).
[`scripts/gala/verify.sh`](scripts/gala/verify.sh) reports `OK (30 twins)` with every regenerated twin byte-identical under a double transpile, `go build ./...` is green, and the canonical Compose backend sequence in [`README.md`](README.md) passes.

### Eight-twin batch (2026-10-25)

A single batch landed eight twins under the same compiler and verifier run, because the full `verify.sh` pass is the expensive step and the candidates are independent.
The batch is `observability/transport`, `services/auth`, `services/calendar/types`, `services/contacts`, `services/listmonk`, `services/microsoftgraph`, `services/gcloud/tasks`, and `mockprovider`; each keeps its Go-facing names, signatures, tags, and wire shapes.

The construct facts the batch settled on the pinned compiler:

- `resource.Bracket` carries a `defer` whose release returns an error once the release body spells the call as `FromError(r.Body.Close())`; a bare `r.Body.Close()` is refused because a void lambda cannot discard the error.
- A declared Go result list whose error is a concrete pointer type lowers from a plain tuple return, as `([]models.User, *errs.GoogleAPIError)` did in `contacts.gala`, while an `error` result takes `Success`/`Failure` and an expression body wraps `resource.Bracket` without leaving `std`.
- An empty named map literal (`http.Header{}`, `url.Values{}`) is direct in GALA and emits the same Go literal, which keeps `Transport`'s nil-header guard and the OAuth form payload exact.
- A `match` arm that returns must be a block (`case X => { return ... }`), and a non-sealed match still needs `case _`; the same goes for the fall-through case the original `switch` left to the trailing `return nil`.
- Package-level constants became `var`s in `mockprovider` only where no caller needs constantness, and the mock's `map[string]any` and `[]map[string]any` payloads went through `MapEmpty`/`MapPut` and `SliceOf` with explicit type arguments.
- `services/gcloud/tasks.gala` shows a nested protobuf keyed literal (`&cloudtaskspb.CreateTaskRequest{...}` with the `Task_HttpRequest` oneof and its `HttpRequest`), a `map[int]*timestamppb.Timestamp` from `MapEmpty[int, *timestamppb.Timestamp]()`, and map-index assignment as direct.
- `services/auth` keeps its tagged `GoogleIdTokenInfo`, the `chan`/`recover` async refresh, and the channel-driven `RefreshUserTokenIfNecessary` in `auth_extra.go`; the verification and token-exchange members moved because none of their signatures or wire shapes changed.
- `services/microsoftgraph` and `services/calendar/types` stay runtime-free (their generated Go names no runtime package), the latter because `GetCalendarProvider` only compares defined-type constants and returns sibling-declared structs.

Each twin's generated imports name only `go.gala.fyi/stdlib/...` where it uses the runtime, and each sibling is handwritten and gofmt-clean.
The batch's evidence is one full `verify.sh` run, a module-wide `go build ./...` and `go vet ./...`, and the canonical Compose backend sequence from `server/README.md`.

## Compiler

The translation target is the `gala` compiler the dev shell puts on `PATH`, and every committed twin regenerates byte-identically under it.
The compiler is the flake-locked commit; `gala version` reports `0.93.0`, and the current rev `8ba02b2b` is the post-release `master` HEAD, the merge of the [0.93.0 release](https://github.com/martianoff/gala/releases/tag/0.93.0) version bump.
The 0.93.0 range covers [0.92.2](https://github.com/martianoff/gala/releases/tag/0.92.2) and [0.93.0](https://github.com/martianoff/gala/releases/tag/0.93.0): 0.92.2 caches path resolution in the analyzer and module resolver and makes `gala test` and `gala build ./cmd/<name>` copy the files a `//go:embed` pattern names, while 0.93.0 adds `Option.Exists`/`Option.ForAll`, hash-based `Distinct` on primitive collections with an `std.Equal` fast path, the new diagnostics `GALA-E0081` (a struct field and a method with one name), `GALA-E0082` (wrong argument count) and `GALA-E0083` (another package's unexported method), cross-package default and package-level `val` inference fixes, a pointer-preserving `std.Copy`, and the behavior change that a named import binds only its qualifier.
All 30 twins regenerated byte-identically on 2026-10-25, so this range changed no generated Go in the repository: the 30-twin `verify.sh --write` reported every twin unchanged, `go build ./...` passed, and the six committed probes reproduced their recorded results.

The GALA runtime is not vendored as a source tree.
`server/go.mod` requires the published module `go.gala.fyi/stdlib v0.93.0` with no `replace` and zero transitive requirements, fetched like any other Go module; [`server/tools.go`](tools.go) still anchors the requirement under the `tools` build tag, though the migrated twins now import the runtime directly.
`server/Dockerfile` copies no runtime tree: the production `testdeps` stage fetches the module through `go mod download`, and the Compose test containers fetch it lazily into the `timeful-test-go-mod-cache` volume when a package imports it.
[#698](https://github.com/martianoff/gala/issues/698) asked upstream to publish the transpiled stdlib for plain-Go consumers.
Upstream first recommended `gala build`, which the [counter-repro posted on 2026-10-05](https://github.com/martianoff/gala/issues/698#issuecomment-5996259351) showed is not a substitute, then closed the issue on 2026-10-09 by publishing every release's stdlib as the Go module `go.gala.fyi/stdlib`, with no `replace` directives, and adding `gala stdlib export`.

TASK-0353 adopted the module on 2026-10-10; TASK-0353.01 landed the build and verification side, TASK-0353.03 migrated the twins, and the flag [`--stdlib-module`](https://github.com/martianoff/gala/pull/743) is what writes the module path into generated imports.
`verify.sh` applies the flag on every transpile and rejects only `martianoff/gala`.

When the flake rev and `GALA_COMPILER` disagree, stop translating and run a bump iteration first.
The version string alone cannot identify the compiler, because several commits share one version string and a rev can share its stdlib fingerprint with an earlier one (as the 0.90.0 line did), so the flake rev is the compiler's identity and the marker proves which stdlib extraction it carries.

1. Enter `nix develop` so `gala` is the flake-locked compiler, and record `gala version`, `which gala`, and `jq -r '.nodes.gala.locked.rev' flake.lock`.
2. Force the pinned compiler to write its own extraction: delete `$GALA_HOME/stdlib/v<version>/.stdlib-extracted`, then run one transpile from a package directory, for example `cd server/eventid && gala transpile -i eventid.gala -o /tmp/eventid.go`.
   The dev shell sets `GALA_HOME` to `.local/gala` inside the checkout (see [`.envrc`](../.envrc)); when it is unset the compiler uses `~/.gala`, and `verify.sh` reads the marker from the same place.
   The transpiler resolves the stdlib on every run and rewrites the version directory when the marker is missing or names a different embedded snapshot, so the extraction at that path afterwards belongs to the pinned compiler.
3. Read `$GALA_HOME/stdlib/v<version>/.stdlib-extracted`; it is `<version> <snapshot fingerprint>`.
4. Write `GALA_COMPILER` with the compiler version, the flake rev, the extraction marker contents, and the date.
5. Run `scripts/gala/verify.sh --write`, review the per-twin diff, then run `go build ./...` in `server/` and the canonical backend test sequence in [`README.md`](README.md).

A rev mismatch is resolved by a bump iteration and never by translating across it, because a twin generated by one compiler is not reproducible under another.

## Open findings

The loop re-checks a report's finding on the pinned compiler before relying on it, because "closed" and "in the pinned rev" are different claims.

## Cursor

The cursor is ordered, and the loop takes the next workable entry and re-checks its constructs on the pinned compiler before translating.
An entry that lists more than one candidate states the candidates' order and any dependency between them, so the next pick is unambiguous.
An entry whose candidates stay blocked records the compiler rev its blockers were last re-verified on, so the loop knows whether re-probing them carries new information.
A fixed blocker moves the candidate forward; a persistent blocker with no workaround becomes a Backlog task and a probe, and the candidate stays.

1. `models/set.go`, `models/location.go`, `models/event.go` — all three are blocked on `struct{}` and tags with no dependency among them, and the listed order is by size and blocker count (`set.go` is three lines, `location.go` thirteen, `event.go` the tag-heavy one); blockers last re-verified on rev `8ba02b2b` (2026-10-25) with probes at `scripts/gala/probes/models-*`; `models/datetime.go` and `models/uuid.go` are migrated (the runtime-synthesized `Hash`/`Compare` replaced the siblings in TASK-0353.03), with uuid's fixed-size `[16]byte` helpers still in `models/uuid_extra.go`.
2. `routes/transfers.go` — a whole-file candidate after the fourth batch: `transferSecret` already returns the token and digest, `createTransfer` binds a tagged body that would move to a sibling, and `transferAction` is a handler over `provenGrant` and the transfer repository methods.
   Neither the file nor its tagged bodies were transpiled, so the loop re-checks its constructs first.
3. `routes/auth.go` — `signIn`, `signInMobile`, `signInHelper`, `signOut`, `getStatus`, `generateOtpCode`, `checkEmail`, `sendOtp`, and `verifyOtp`; its three anonymous request bodies move to a sibling, and `signInHelper`'s provider fan-out is the member to triage first.
4. `routes/user.go`, then `routes/event_routes.go` — the two largest handler files, ordered by size; `event_routes.go` holds the channel and `recover` members (`routes/group_extra.go`'s finding covers the same shape) and every response-identity helper, so a split that leaves those members handwritten is the expected verdict.
5. `postgres/otp.go`, then `postgres/identities.go` — free-function splits only: `otp.go`'s five OTP helpers and `identities.go`'s two validators are the movable members, because a `*Repository` method declared in a `.gala` file makes the receiver's method set GALA-resolved and hides the eighteen methods `postgres/repository_methods.go` declares, so the methods stay handwritten until the whole receiver moves together.
6. `observability/metrics.go` is landed, and the remaining `observability` siblings are boundary members rather than candidates.
7. `services/calendar/calendar.go`'s two `recover`-guarded broadcast helpers and `GetUsersCalendarEvents` stay handwritten until the channel/recover findings close; the four provider files landed on 2026-10-25 and no new candidate depends on them.

## Stop conditions

Stop and report when any condition in [`Stop And Report`](../.agents/skills/gala-from-go/SKILL.md#stop-and-report) holds, and obey its `Never` list.
The project additions are:
no hand-edited generated twin; no transpile from the repository root; no reshaped Go-facing signature or wire format; no relaxed test; and no translation across a compiler rev mismatch, because a bump is its own re-baseline iteration.
