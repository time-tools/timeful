## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Phase 2 of TASK-0224. Use the TASK-0224.01 audit results to clean the reported violations and finish the FR-119 event-name constraint lifecycle.

The constraint was added NOT VALID by server/migrations/20260913000002_postgres_events_name_length.sql so legacy over-limit or empty rows would not fail the migration. Postgres then checks every new insert and update but never validates existing rows, and the repository currently hard-asserts convalidated = false in server/postgres/name_constraint_test.go.

Outcome: every violation class from the audit is resolved or explicitly accepted, and every database reaches a recorded final state: either the constraint is validated after cleanup, or the database is recreated from the baseline under the documented policy. Do not clean legacy data in a database that predates the baseline; recreate it instead. Record each command and its result as task evidence.
