## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Outcome

Remove the app shell's non-critical dialogs and their exclusive component dependencies from the initial eager bundle so first load no longer downloads dialog-only Vuetify components and form code.

## Context

- `frontend/src/App.vue` statically imports `SignInNotSupportedDialog`, `GrantedAccessConfirmation`, `SignInDialog`, `NewDialog`, and `UpvoteRedditSnackbar`; `NewDialog` statically pulls in `NewEvent`, `NewGroup`, `NewSignUp`, and `UnsavedChangesDialog`.
- The recorded eager preload set from the built `index.html` includes VDialog, VImg, VChip, VInput, VCheckbox, and VSpacer chunks, and the entry chunk is 237 KB raw / 75 KB gzip.
- Dialog components are still rendered conditionally; their visible behavior and `v-model` contracts must not change.
- `AutoSnackbar` is always active in the shell and is not a candidate for deferral.

## Constraints

- Keep the existing component contracts and unit tests intact; update tests only where the loading mechanism changes observable timing.
- Each deferred dialog must still open on first interaction, including when it is opened before its code has been fetched.
- An empty or broken first-open experience is a regression, not an acceptable tradeoff.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
## Baseline (before)

Measured from `frontend/dist/index.html` after `npm run build` (mode production), raw sizes from disk and gzip from `zlib.gzipSync` level 9:

- Entry chunk `index-DvYsH5fr.js`: 262.68 KB raw / 87.07 KB gzip.
- Initial modulepreload set: 21 JS files, 776.32 KB raw / 272.70 KB gzip.
- Dialog-only chunks in the eager set include `VDialog`, `VImg`, `VCard`, `VInput`, `VDivider`, `VChip`, `VCheckbox`, `VSpacer`, and `transition`.

## Plan

1. In `frontend/src/App.vue`, replace the five static dialog imports with `defineAsyncComponent(() => import(...))` so Rollup emits them as dynamic chunks.
2. Gate each async dialog render so its chunk is requested only when the dialog can appear, and latch the gate after the first request so an open dialog is never unmounted at close (preserves Vuetify close transitions and internal state):
   - `SignInNotSupportedDialog`: latch on `webviewDialog`.
   - `GrantedAccessConfirmation`: `v-if="authUser"` (transfer consent only exists for a signed-in account); unmounts on sign-out as before.
   - `SignInDialog`: latch on the local `signInDialog` flag, which is the dialog's only open channel.
   - `NewDialog`: latch on `newDialogOptions.show`; add a pointer-intent preload on the header create controls so a first click does not wait on a cold fetch.
   - `UpvoteRedditSnackbar`: latch on first `route.name === "home" && !isPhone`.
3. Update `frontend/src/App.test.ts` only for the SignInDialog stub test, where the lazy gate now controls mount timing: set the local `signInDialog` flag before clicking the stub.
4. Verify: rebuild and diff entry chunk plus modulepreload set; run `npm run lint`, `npm run fmt:check`, `npm run typecheck`, `npm run build`, `npm run test:unit`; run the Firefox e2e project because the create-event and access-transfer specs exercise the deferred dialogs.
5. Record before/after evidence and any check that could not run in this task.
