## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
# Goal

Add the indexes that existing query shapes need and stop defeating indexes with UUID-to-text casts.

# Scope

- Add one goose migration in `server/migrations/` covering the indexes below.
  Keep it compatible with the temp-table migration harness at `server/postgres/migration_helpers_test.go:57-59`: plain `CREATE INDEX`, no `CONCURRENTLY`, and no schema-qualified names.
  - `postgres_event_responses (event_id, created_at, id)` for the `ListResponses` ordering in `server/postgres/repository.go`, and drop the now-redundant `postgres_event_responses_event_id_idx` in the same migration.
  - `event_attendees (event_id, created_at, id)` for the `ListAttendees` ordering in `server/postgres/attendees.go`, and `event_attendees (event_id, lower(email))` for the dashboard membership EXISTS in `server/postgres/dashboard.go`.
  - A `postgres_events` index that serves the analytics day-spine windows in `server/postgres/analytics.go`, with columns and predicate stated explicitly (candidate shapes: `(created_at, creator_posthog_id)`, `(created_at) INCLUDE (creator_posthog_id)`, or a partial index on non-empty `creator_posthog_id`).
    The existing `postgres_events_active_creator_posthog_id_idx` is partial `WHERE NOT is_deleted` and cannot serve these queries because analytics deliberately does not filter `is_deleted`; record whether that now-unused partial index stays or is replaced.
  - `daily_user_log_members (daily_user_log_id, first_seen_position, id)` to match the `ORDER BY ... m.first_seen_position, m.id` in `ListActiveUserDays` and the `MAX(first_seen_position)` append path.
  - Decide and record whether `event_signup_responses (event_visitor_identity_id)` is needed for account-deletion scans; removing the `::text` cast in `deleteAccountAuthority` restores no index because none exists on that column today.
- After TASK-0214.03 lands, re-locate every line reference against the post-TASK-0214.03 code and replace the remaining `::text` casts on UUID columns with typed UUID binds plus validation:
  - `GetEventVisitorIdentity`, `GetEventVisitorCredential`, and `GetResponseByPublicID` in `server/postgres/identities.go` (the last one was missed by the original audit and must be included; it backs client `responseId` on `server/routes/postgres_event_routes.go` and `server/routes/postgres_group.go`).
  - `LockAccessTransfer` in `server/postgres/transfers.go`.
  - `deleteAccountAuthority` in `server/postgres/accounts.go` (typed `uuid[]` bind, type consistency only).
  - `GetSignupResponseByPublicID` and `DeleteSignupResponse` public_id lookups in `server/postgres/signup.go` (TASK-0214.03 removes the block-membership casts).
- Validate opaque client identifiers inside the repository with `models.ParseUUID` before binding, following `validPlatformIdentityID`/`guardPlatformIdentityID`; do not push UUID parsing into routes.
  - Non-canonical identifiers keep returning `pgx.ErrNoRows` at the repository boundary so each caller preserves its existing mapping: 404 for response, signup-response, and transfer lookups; anonymous/no-credential handling for event-visitor public ID and credential lookups.
  - Non-canonical signup block identifiers must keep `ErrSignupBlockNotFound` (400 `signup-block-not-found`), never `pgx.ErrNoRows` or `22P02`.
    Resolve with TASK-0214.03 whether block-ID validation lands there (its constraints require no cast error) or here (its notes defer it); if here, specify the `normalizeSignupBlockIDs` or capacity error path, because that helper currently returns `[]string` only.

# Constraints

- The baseline migration is immutable; add a new migration instead.
- Preserve not-found behavior for non-canonical IDs; do not surface `22P02` errors to routes.
- Do not map non-canonical signup block identifiers to `pgx.ErrNoRows`; their contract is `ErrSignupBlockNotFound`.
- SQL stays in `server/postgres/`.

# Verification

- Seed representative rows (or force plans with `SET enable_seqscan = off`) before `EXPLAIN (ANALYZE, BUFFERS)`; an empty isolated test database yields seq scans and proves nothing.
- Confirm index usage for the analytics, response-listing, attendee-listing, daily-log, and transfer-lock queries.
- Add non-canonical regression tests for every newly typed bind (event-visitor public ID, credential ID, response public ID, signup response public ID, transfer ID) asserting `pgx.ErrNoRows`; keep signup block-ID tests asserting `ErrSignupBlockNotFound`.
- Run the route and repository test suites under `compose.test.yaml`.
