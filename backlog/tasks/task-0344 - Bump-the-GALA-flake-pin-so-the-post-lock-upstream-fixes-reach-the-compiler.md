## Blocker discovered (2026-10-04): the pinned rev's dev-shell compiler does not build

The staged bump to `2ecf1f0d39c92596be0f85c61cd62e0989418d6d` (upstream HEAD; `git ls-remote` confirms HEAD == locked rev) makes `nix develop` fail before it can start. The failing derivation is `gala-stdlib-0.84.1` built by `gala-local`'s local-bootstrap path: `gala: transpiling 53 files (local bootstrap)` then `Error: test/assertions.gala: [SemanticError GALA-E0023] test/assertions.gala:12:17 undefined: T (hint: T is declared in the GALA package "martianoff/gala/test", which this file does not import. ...)`. No `nix develop` shell can be entered at this rev, so the plan's step 2 (dev-shell compiler for every command) cannot start.

Root cause: the #648 fix (upstream `3120538d`, "a type name that nothing declares is a GALA error") adds the strict type-position check. The local bootstrap batch mode relies on the analyzer's directory-discovered siblings, but `internal/transpiler/analyzer/analyzer.go` skips directory discovery for packages named `main` or `test` (`pkgName != "main" && pkgName != "test"`). The shipped stdlib package `test` declares `T` in `test/framework.gala` and uses it in `test/assertions.gala`, so the new check refuses to transpile the compiler's own stdlib. Reproduced on the host with a bootstrap built from the checkout at the locked rev: the same error, exit 1.

## Upstream report: `gala-local` does not build at 2ecf1f0d

Title: the nix `gala-local` bootstrap cannot transpile the stdlib's `test` package after the #648 type-position check.

Classification: defect, build regression; the released compiler is unaffected, so this is a toolchain defect in the local-bootstrap path rather than a language gap.

Minimal reproduction:

```sh
nix build 'github:martianoff/gala/2ecf1f0d39c92596be0f85c61cd62e0989418d6d#gala-local'
```

Observed: the `gala-stdlib-0.84.1` derivation fails with `gala: transpiling 53 files (local bootstrap)` then `Error: test/assertions.gala: [SemanticError GALA-E0023] test/assertions.gala:12:17 undefined: T (hint: T is declared in the GALA package "martianoff/gala/test", which this file does not import. ...)`, exit 1.
Control: `nix build 'github:martianoff/gala/2ecf1f0d39c92596be0f85c61cd62e0989418d6d#gala'` succeeds because the default package transpiles the stdlib with the 0.84.0 release's `transpile-package`, which passes explicit package input lists.
Host reproduction without nix: build `cmd/gala_bootstrap` from the tree and run it in batch mode over `test/assertions.gala,test/bench.gala,test/framework.gala,test/table.gala` with `--search <tree>`; the same GALA-E0023 fires, exit 1.

Root cause: the #648 fix (`3120538d`, "a type name that nothing declares is a GALA error") requires an unqualified type name to resolve to a package symbol.
The local bootstrap's `runBatch` (`cmd/gala_bootstrap/main.go`) calls `a.SetPackageFiles(nil)` and relies on directory-discovered siblings.
`internal/transpiler/analyzer/analyzer.go` skips directory discovery when `pkgName == "main" || pkgName == "test"` (`} else if filePath != "" && pkgName != "main" && pkgName != "test" {`), so the shipped stdlib package named `test` never loads `test/framework.gala`'s `T` while transpiling `test/assertions.gala`, and the new check refuses the name.
The check stands down when the package cannot be resolved, which is why the committed #648 probe alone (without a resolvable stdlib on `--search`) does not fire.

Expected fix: the local-bootstrap path needs to give the analyzer the package's sibling set, or the analyzer's test-package heuristic needs to distinguish a directory of independent `main`-like programs from a shipped library package named `test`.
Candidate one-line nix fix: pass `--package-files` (the non-test `.gala` siblings) per package in `nix/gala.nix`'s `useLocalBootstrap` branch, matching what the release's `transpile-package` does.

Upstream state at the time of writing: `2ecf1f0d` is upstream HEAD, so no newer revision carries a fix; nothing in the open PRs (#672-#677) touches the nix local bootstrap.
