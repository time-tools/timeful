## Outcome

Reduce the production CSS payload by no longer shipping Vuetify component or utility rules the app does not use, with visual parity across routes.

## Context

- `frontend/src/plugins/vuetify.ts` imports the full `vuetify/styles` bundle.
- The recorded built app stylesheet is 268,751 bytes (~40 KB gzip); roughly 85 KB raw of its rules are Vuetify utility classes such as `text-*`, `bg-*`, `m*-*`, and `rounded-*`, and the remainder includes every Vuetify component's CSS.
- The app uses a scoped Vuetify component set and Tailwind utilities with the `tw` prefix, so Vuetify utility classes may be largely unused.
- `vite-plugin-vuetify` supports styles modes that allow per-component CSS import strategies.

## Constraints

- Correct rendering is mandatory; a missing component style is a regression, not an acceptable saving.
- Verify at minimum the Landing, Home, Event, Settings, and SignIn routes in a real browser.
- Do not change component markup or class names to fit a CSS strategy.
- This task edits `frontend/src/main.ts` like the font-subset task; do not run the two in parallel.
