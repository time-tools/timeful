## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Phase 1 close-out follow-up of TASK-0224. TASK-0224.01 established that the development database was recreated from the baseline and that staging and production are handled by recreation rather than in-place cleanup. This task performs that recreation.

Outcome: every deployed database in scope is either recorded as already baseline-created or recreated from the baseline with a verified backup retained, and the observed constraint state is recorded so TASK-0224.02 and TASK-0224.03 can proceed.

Per-environment procedure:
1. Detect schema generation and record the basis: migration_ledger and migration_quarantine presence, goose_db_version containing retired versions below 20260912000000, and presence of baseline signature tables such as platform_identities.
2. For a pre-baseline environment, take a custom-format pg_dump with the backup role and verify the restore into a scratch database by reconciling counts and key digests before any destructive step, per docs/postgres-operations.md.
3. Recreate the database from the baseline and apply all migrations through the current version, then confirm the application stack reaches healthy status against it.
4. Record the FR-119 constraint state and keep the old backup intact until the replacement database is validated.

Constraints: the data reset is accepted for staging and production, so no data migration is in scope; no application code changes are in scope; if an environment turns out to hold data that must survive, stop and report instead of recreating. Coordinate backup-verification tooling with TASK-0226. The retained pre-baseline development evidence is at ~/timeful-backups/prebaseline-dev-20260914/.
