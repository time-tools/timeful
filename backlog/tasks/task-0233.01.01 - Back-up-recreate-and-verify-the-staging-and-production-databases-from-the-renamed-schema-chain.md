## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Outcome: staging and production run on the edited migration chain from TASK-0233.01, expose only events and event_responses with no postgres-prefixed relation, constraint, or index, and each has a retained, verified pre-recreate backup with recorded evidence.

Context:
- Staging and production are remote Compose deployments (projects timeful-staging and timeful-production) on the deployment host; this task runs there, not in the local checkout.
- TASK-0233.01 edits the baseline and incremental migrations in place, renaming postgres_events to events, postgres_event_responses to event_responses, and dropping the postgres_ prefix from related constraints and indexes; no rename migration exists, so a database not recreated from the edited chain silently keeps the old schema while the new code expects the new names.
- Pre-rename server binaries are incompatible with the renamed schema, so the renamed server code (TASK-0233.01 through TASK-0233.04) and the edited chain ship in one release, and rollback requires restoring a backup plus the previous release.
- Recreating a database destroys data accrued since the last recreate unless that data is carried over from the backup.

Required work:
- Back up each environment with the custom-format pg_dump procedure in docs/postgres-operations.md, verify each archive by restoring it into a scratch maintenance database and reconciling per-table row counts and key content digests, and retain the verified archives outside the environment data volumes.
- Record per-table row counts and the events_name_length constraint validation state (convalidated from pg_constraint) before recreation.
- Recreate each environment's database from the edited chain by discarding the environment's PostgreSQL data volume and letting postgres-migrate apply the full chain with the renamed release, following docs/environments.md, then carry data over from the verified backup or record the explicitly approved decision to discard it.
- Verify each recreated database has no postgres-prefixed relation, constraint, or index, that events_name_length is validated, and that /api/health reports healthy for the environment.
<!-- SECTION:DESCRIPTION:END -->
