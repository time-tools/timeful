## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Phase 1 of TASK-0224. The compatibility code named in the parent description exists to tolerate legacy row shapes from the MongoDB era, but no database has ever been audited to establish which shapes are actually present. The audit target for this phase is the development database timeful-postgres-development; deployed staging or production databases and retained backups are audited only if the user names them.

Outcome: a repeatable, read-only audit that classifies every compatibility-shaped legacy row in each audited PostgreSQL database and records the counts in the task record as evidence for the later phases. The audit must not modify data. It detects pre-baseline schema generation (migration_ledger presence, docs/postgres-operations.md) and records classes its schema cannot support instead of failing. Where a database predates the baseline, the recreate-from-baseline policy in docs/postgres-operations.md applies instead of in-place cleanup; record that state rather than attempting repairs here.

The seven classes to classify:
1. postgres_events.name that is empty or longer than 100 characters.
2. calendar_preferences.calendar_options that is not a JSON object (jsonb_typeof distinct from object).
3. calendar_accounts.calendar_key values that are not canonical for their calendar_type (email-like keys are lower-case trim; ICS labels are trimmed only).
4. postgres_event_responses.respondent_kind that is NULL or empty (empty is rejected by the row CHECK, so NULL is the expected legacy shape).
5. postgres_event_responses rows with populated guest_id, canonical_guest_name, guest_edit_policy, guest_ownership_mode, or guest_edit_token.
6. Stored JSONB payloads carrying account or event identifiers that are not canonical UUIDs, checked at the retired keys postgres_events.payload _id, ownerId, signUpResponses, responses and postgres_event_responses.payload userId, user.
7. Rows whose parent is missing (orphans) across event, response, attendee, signup, signup-membership, folder, calendar, and daily-log relations.

The epoch-millis/RFC3339 dual signup-instant decoding named in the parent compatibility surface is not auditable from stored rows and is retained with that recorded reason.
