## Context

TASK-0353 decides that server GALA twins adopt the published module `go.gala.fyi/stdlib`, and TASK-0353.01 lands the `server/go.mod`, `verify.sh`, and ledger contract change. The translation guidance still encodes the runtime-free-only policy: `gala-loop`'s stop conditions ban any twin whose generated Go imports the GALA runtime, and `gala-from-go`'s traps and construct reference assume runtime constructs are excluded from twins.

## Outcome

The `gala-from-go` and `gala-loop` skills match the adopted contract so a future loop session can emit and verify runtime-enabled twins without contradicting the guidance.

## Required updates

- `gala-loop`: the regeneration command gains `--stdlib-module go.gala.fyi/stdlib`; the runtime stop condition becomes "never import `martianoff/gala`; a runtime import must be the `go.gala.fyi/stdlib/...` module pinned in `server/go.mod`"; preconditions, registry/registration steps, and verification text follow.
- `gala-from-go`: remove project-level runtime-free restrictions while keeping every construct-shape rule; state which runtime constructs are now available (`val`, `Try`, `Option`/`Either`, sealed types, immutable collections, `go_interop` helpers) and which spellings remain boundary-changing for a Go-facing surface (exported `val`, sealed types, non-`var` struct fields, `Codec` wire shape).
- Keep `references/constructs.md` and `references/gaps.md` consistent with the pinned compiler `cd2fdcb5`; re-run any affected checks rather than copying rows.
- Cross-check `server/GALA.md` links and the models-group blocker prose so nothing promises runtime freedom.
- Documentation-only: changed Markdown formatted with `npm run format:markdown`; no runtime code, tests, or generated twins change.
