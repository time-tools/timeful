## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Outcome

Make the roster's substitutions directly appliable, one rule at a time, and prevent that list from drifting away from the verdicts it is derived from.

An agent rewriting Go to GALA must currently join the `Minimal Go`, `GALA rule`, and `Verdict` cells across an eleven-column table row, and the rule cell is prose rather than something it can write down and apply.
The information is correct; it is in the wrong shape.
A catalog in the roster keeps the single source of truth while giving the rewriter a copyable rewrite, and an audit gate keeps the two consistent so the catalog cannot rot into a second, silently divergent answer to the same question.

TASK-0326 already established the pattern this extends: a genuine claim is backed by a probe, and `audit.sh` checks roster, corpus, and `server/GALA.md` against each other in both directions.
The catalog is a new class of claim with the same requirement, and the same two-way gate.

## Requirements

- The roster gains a section of mechanical rewrites: one row per rule rather than per construct family, pairing a Go spelling with the GALA spelling that replaces it, the note a rewriter needs to get it right, the probe that pins it, and the construct families the rule covers.
- A construct family with a substitute is covered by at least one catalog row, and a family with no substitute is not given one.
- Every catalog row is traceable to a probe that exists in the corpus.
- The audit script fails when a catalog row names a probe that does not exist, when a construct family with a substitute has no catalog row, and when a catalog row claims a construct family the roster does not classify as substitutable.
- The audit script's existing construct-class lookup and the new catalog check read the same authoritative slice of the roster, so neither can be influenced by tables on the page that are not the construct roster.

## Constraints

- The catalog lives inside `docs/gala-translation.md`.
  A separate catalog document would be a second source of truth and is out of scope.
- The catalog is derived from the roster's existing verdicts.
  This task adds no new verdict, probe, gap class, or `GAP-n` entry, and changes no occurrence count.
- `audit.sh` stays read-only and free of a GALA and Go toolchain, and its existing checks keep their current messages and exit behaviour.
- A construct family may appear on more than one catalog row where a decision rule has genuinely different branches, such as a byte count against a character count.
  The note carries the condition that selects the branch, and each branch names its own probe.
- Constructs with no substitute are recorded as having none, so that a rewriter learns the absence rather than inferring an omission.
- Corpus commits stay limited to `.gala` sources, `expect`, `expected.out`, `go.mod`, `.gitignore`, `run.sh`, and the inventory tooling.

## Evidence required

- `audit.sh` output showing a seeded catalog inconsistency failing and then passing after the seed is reverted, with both outputs.
- A seeded edit outside the construct roster section shown to leave the class check and the catalog check unaffected.
- The corpus run, recorded in the task notes.

## Plan

Baseline: `audit.sh` reports 5 `ok` lines and `audit passed`; the roster's substitutable set is the 22 families whose `Gap class` is `analog` or `workaround`, which the Gap classification section defines as the rows with a substitute rather than a gap.

### Roster

1. Add a `## Mechanical rewrites` section after the replacement summary, with one row per rule: `Go spelling`, `GALA spelling`, `Note`, `Probe`, `Construct families`.
2. Take every GALA spelling from the probe sources and the committed twins rather than from prose, and confirm each helper name against the vendored runtime, so a row is copyable.
3. Split a family's rows where its decision rule has genuinely different branches, and give each branch its own probe.
4. Record the families with no substitute as a small gap-class-keyed index, so the absence is stated rather than inferred.
5. Record `—` in the Probe column for a family the roster itself gives no probe, following the roster's existing convention.

7. Point the pre-existing class lookup at that file, which also makes it read the same authoritative slice the new check reads.
8. Add check 6: a row probe must exist and must be one the roster records for a family the row covers; a substitutable family must have a row; a row may not claim a non-substitutable family; the no-rewrite index must list exactly the non-substitutable families under the matching gap class and be disjoint from the rows.
9. Keep every pre-existing message and exit behaviour, and add no Go or GALA toolchain dependency.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## What landed

`docs/gala-translation.md` gains a `## Mechanical rewrites` section with 38 rule rows and a 3-row no-rewrite index, and `audit.sh` gains a sixth check that gates them against the construct roster.

Catalog shape: `| Go spelling | GALA spelling | Note | Probe | Construct families |`, one row per rule rather than per family. The GALA spellings are the qualified `go_interop.` and `resource.` forms the committed twins already use, taken from the probe sources and confirmed against the vendored runtime's exported names, so a row can be copied rather than paraphrased.

Branched families get one row per branch, each naming its own probe: `len-calls` (bytes against characters), `make-calls`, `map-literals`, `slice-literals`, `append-calls`, `delete-calls` (Go container against GALA collection), `switch-statements` (literal against identifier cases), `if-initializers` (statement against value flow), `panic-calls` (recoverable against invariant), `defer` (three acquire shapes), and `const-declarations` (`var` against `val`).

`close-calls` is the one substitutable family the roster gives no probe for, anywhere, so its row carries `—` in the Probe column, which is the roster's existing convention for a row with no scripted pin, and its note says the roster keeps the family handwritten today. `copy-calls` and `interface{} type` are classified `workaround` but their roster verdicts say keep handwritten, so their rows say so rather than implying they are free to rewrite.

The 28 families with no substitute are listed in a gap-class-keyed index, 17 direct forms, 7 language gaps, 4 boundary gaps, so a rewriter reads the absence instead of inferring an omission.

## The gate

`audit.sh` now extracts the construct roster into one temporary file with a new `section_of` helper that skips fenced code blocks, and both the pre-existing class lookup and the new catalog check read that file. The pre-existing lookup previously read the whole page, which meant the replacement summary, which repeats the `Construct` and `Gap class` headers, could overwrite a family's classification; the seeded comparison below is the proof.

Check 6 fails on a row probe that the corpus does not have, a probe the roster does not record for a family the row covers, a substitutable family with no row, a row claiming a family the roster does not classify as substituted, a family missing from the no-rewrite index, a family in the index under the wrong gap class, and a family in both places. It uses bash, awk, sed, and grep only, writes nothing, and every pre-existing message and exit code is untouched.

### Seeded catalog inconsistencies, failing then passing after the revert

```
FAIL catalog row 15: probe pass_slice_rangez does not exist

```

After each revert the audit returns to the six `ok` lines above. The first two seeds caught defects in the catalog as first drafted, which is the gate doing its job: a `contested_*` probe had been named in a Probe cell although the roster pins that family with other probes, and `interface{} type` was being split on whitespace by the family parser. The contested probe moved into the note prose where the roster records it, and the parser now reads backticked spans.

Swapping either emitted field of the new awk was used as a control: swapping the index row's fields produces 31 failures and swapping the rule row's produces 114, so neither path is silently inert.

### Seeded edits outside the construct roster

Three seeds, each leaving both the class check and the catalog check at the baseline with `audit passed`:

- a decoy `struct-tags` row classified `—` seeded into the replacement summary table, which repeats the `Construct` and `Gap class` headers;
- a decoy `select-statements` row classified `workaround` seeded into the same table;
- a decoy row seeded into the version matrix.

The pre-existing `audit.sh`, restored from HEAD and run against the first of those seeds, fails:

```
FAIL struct-tags appears in a GAP-n row but is classified '—'

audit failed: 1 problem(s)
```

That is the concrete reason the class lookup had to become section-bounded: it was reading a table that is not the construct roster and taking a family's classification from it.

Every table row in the new section is on one physical source line, enforced by the repository's own Markdown formatter.

### Derived, not invented

The catalog adds no construct family, verdict, gap class, `GAP-n` entry, probe, or occurrence count. The gate enforces the probe half of that mechanically: a row may only name a probe the roster already records in the Probe cell of a family the row covers, which is what caught the contested-probe mistake above. `go run ./inventory -check` still reports `doc matches (166 files)`, so no occurrence count moved.
