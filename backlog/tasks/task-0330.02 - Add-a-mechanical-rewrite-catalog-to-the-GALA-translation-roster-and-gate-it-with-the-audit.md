## Outcome

Make the roster's substitutions directly appliable, one rule at a time, and prevent that list from drifting away from the verdicts it is derived from.

An agent rewriting Go to GALA must currently join the `Minimal Go`, `GALA rule`, and `Verdict` cells across an eleven-column table row, and the rule cell is prose rather than something it can write down and apply.
The information is correct; it is in the wrong shape.
A catalog in the roster keeps the single source of truth while giving the rewriter a copyable rewrite, and an audit gate keeps the two consistent so the catalog cannot rot into a second, silently divergent answer to the same question.

TASK-0326 already established the pattern this extends: a genuine claim is backed by a probe, and `audit.sh` checks roster, corpus, and `server/GALA.md` against each other in both directions.
The catalog is a new class of claim with the same requirement, and the same two-way gate.

## Requirements

- The roster gains a section of mechanical rewrites: one row per rule rather than per construct family, pairing a Go spelling with the GALA spelling that replaces it, the note a rewriter needs to get it right, the probe that pins it, and the construct families the rule covers.
- A construct family with a substitute is covered by at least one catalog row, and a family with no substitute is not given one.
- Every catalog row is traceable to a probe that exists in the corpus.
- The audit script fails when a catalog row names a probe that does not exist, when a construct family with a substitute has no catalog row, and when a catalog row claims a construct family the roster does not classify as substitutable.
- The audit script's existing construct-class lookup and the new catalog check read the same authoritative slice of the roster, so neither can be influenced by tables on the page that are not the construct roster.

## Constraints

- The catalog lives inside `docs/gala-translation.md`.
  A separate catalog document would be a second source of truth and is out of scope.
- The catalog is derived from the roster's existing verdicts.
  This task adds no new verdict, probe, gap class, or `GAP-n` entry, and changes no occurrence count.
- `audit.sh` stays read-only and free of a GALA and Go toolchain, and its existing checks keep their current messages and exit behaviour.
- A construct family may appear on more than one catalog row where a decision rule has genuinely different branches, such as a byte count against a character count.
  The note carries the condition that selects the branch, and each branch names its own probe.
- Constructs with no substitute are recorded as having none, so that a rewriter learns the absence rather than inferring an omission.
- Corpus commits stay limited to `.gala` sources, `expect`, `expected.out`, `go.mod`, `.gitignore`, `run.sh`, and the inventory tooling.

## Evidence required

- `audit.sh` output showing a seeded catalog inconsistency failing and then passing after the seed is reverted, with both outputs.
- A seeded edit outside the construct roster section shown to leave the class check and the catalog check unaffected.
- The corpus run, recorded in the task notes.
