## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## The table was answering a question nobody was asking

After TASK-0332.01 the blocked table had 20 rows: 18 `answered`, 1 `semantic`, 1 `gap`. Every column in it was aimed at someone deciding whether to file, and for 19 of the 20 rows the answer was no, so the table was a "What Not To File" list wearing a table costume.

It also carried the file's only stale-by-construction claim. It said its rows were "re-derived by transpiling a minimal repro on the compiler in hand" and to "re-verify a row before relying on it", which means every future session had to re-run twenty transpiles to maintain a table whose rows are stable facts about the language: `match` is the answer to `switch`, a lambda is the answer to a nested function, and the specification says `:=` is immutable. Those do not change between releases.

## The collapse

The section is now `Gaps Worth Filing` and holds `const` alone, with the honest framing that this is the finding rather than an absence.

The removed rows were not deleted so much as unduplicated. `constructs.md` already carries their status and the replacement spelling, which is where a reader actually lands, so the section now says that and points there. The `Code` column went with them because `constructs.md` has a `Code` column for exactly this.

"Constructs That Were Never Gaps" is new and holds the two rows whose value is the reasoning rather than the verdict: a Go function literal inside a composite literal, where a GALA lambda transpiles and builds, and assignment to a `:=` binding, where the specification states the rule. Both were on the old list as if they were findings, and both are the kind of row that returns unless the reasoning is written down. The heading originally said "Three of these" and listed two, which the check caught.

"What Not To File" was restructured so the removed constructs stay findable. Its first four bullets are the ones that look like walls and are not, and they name the `Status` to look up and list the constructs the removed rows covered. The remaining bullets are unchanged except for rewording the `GALA-E0017` one, which conflated a defect with a gap.

Net effect: 60 lines removed, 52 added, and the file is 165 lines rather than 173 despite having gained a section.

## Vocabulary drift found and fixed

The two files had drifted, which is the same class of problem TASK-0332.01 fixed inside one file. `gaps.md` used `analog` where `constructs.md` used `answered`; `gaps.md` had no entry for `semantic` or `defect`; and the `defect` status TASK-0332.01 introduced into `constructs.md` had no counterpart in the classification.

The class table now has a `Status in constructs.md` column. `analog` and `documented answer` both map onto `answered`, `semantic` maps onto itself, the two reportable classes are marked `—` with a note that neither is a property of a single row, and `defect` is called out as the fourth kind of thing that is neither a gap nor a documented answer. `constructs.md`'s legend links back, so a reader who starts at either file can find the mapping.

## Verification

Both "never a gap" claims were re-measured rather than assumed, since the section now asserts them as fact.

- A GALA lambda in a Go call-argument position: `sort.Slice(xs, (a int, b int) => { return a < b })` transpiles to `sort.Slice(xs.Get(), func(a int, b int) bool { return a < b })`, and the program builds and runs. Getting here took discarding two malformed first attempts, one of which used `sort.SliceStable{0: ...}` and the other a nonexistent `go_interop.SliceLen` helper; neither was evidence of anything.
- `:=` immutability: `docs/GALA.MD` states it in the short-variable-declaration section.

Structure was checked directly rather than trusting the formatter, since `scripts/markdown.mjs` excludes `.agents/**`: every table in all three files has a separator row and a consistent cell count, both section anchors resolve, and all relative links resolve. Three apparent broken links turned out to be my own regex matching generic syntax inside code spans, confirmed present at HEAD and untouched.

One caution recorded for the next session: a `git stash`/`git stash pop` cycle used to compare against HEAD staged the earlier hunks, so a plain `git diff --stat` under-reported the change. `git diff HEAD --stat` is the reliable check while the index holds a partial state.
