## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Phase 3 of TASK-0224. Remove the legacy compatibility surface that TASK-0224.01 closed and TASK-0224.04's recreate-and-verify results prove is no longer needed. Candidate classes, each removed only from the recreate decision plus writer-path analysis (TASK-0224.01 reported no live legacy rows, and recreated databases start from the baseline):
- guest_id, canonical_guest_name, guest_edit_policy, guest_ownership_mode, and guest_edit_token compatibility columns and their repository read/write plumbing. Note that canonical_guest_name and respondent_kind still have current writers, so their removal needs a behavior decision, not only row counts.
- NULL respondent_kind coercion and inference, with the column made explicitly NOT NULL if no writer produces NULL.
- Mixed-case calendar_key handling (ActualCalendarAccountMapKey and the legacyKey retry paths in routes/auth.go and routes/user.go) once no non-canonical keys remain.
- Any other recreate-justified dead compatibility code, such as obsolete compatibility indexes.

Retained with recorded reason unless transport-level evidence appears: the epoch-millis/RFC3339 signup-instant decoding and the group manualAvailability dual decoding (legacy millisecond-keyed versus frontend ZonedDateTime-keyed), neither auditable from stored rows.

Constraints: keep PostgreSQL access in server/postgres/; preserve JSONB payload round-trip, blind-availability privacy, EVCC authorization precedence, guest-name normalization, and credential encryption; update server/docs/postgres-data-boundaries.md and server/docs/postgres-anonymous-event-compatibility.md where they describe retired behavior. Do not remove read compatibility that a rollback to the prior server release depends on (docs/environments.md requires incremental migrations to stay compatible with the prior PostgreSQL-aware release); record the retained window. TASK-0216 remains the owner of the anonymous-event-compatibility route-test rename.
