## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Why

Once the verdicts are typed, the page is a rendering. Rendering it by hand means there are still two things to keep in step: the typed table and the Markdown. The page is currently the only place a verdict is visible, so it cannot simply stop being written, but it can stop being authored.

There is a second reason beyond tidiness. The census check currently has an inversion built into it on purpose: the playbook tells an agent that the check is *expected to fail* after adding a twin, and that the failure is the signal to go and edit the page's counts by hand. That is a documented papercut, and it is the mechanism by which the counts got hand-maintained in the first place.

## Outcome

The generated regions of the roster page are written by the tool from the typed data, bounded by explicit markers so the narrative sections are untouched, and the census check becomes regenerate-and-diff instead of edit-by-hand.

## Scope

- **Emit the generated regions.** The census table, the construct roster, workarounds and contested verdicts, the probe tables, the replaced-by-analog-or-workaround table, and the mechanical-rewrite catalog are all written from the typed data. The hand-written regions stay hand-written.
- **Bound the generated regions explicitly** so a regeneration cannot silently swallow a narrative section, and so a hand-written region between two generated ones is preserved byte-identically.
- **Invert the census check.** Regenerate, then diff, and let a non-empty diff be the failure. The playbook's instruction that the check is expected to fail as a signal to hand-edit counts is replaced in the same change, at every place it appears, so no stale window exists between landing this and the playbook reduction.
- **Keep the hand-written prose from restating a generated number.** The census section's prose currently states how many files the walk covers, how many are handwritten, and how many generated files split into GALA twins versus swag output. Those are generated. A sentence that restates a generated number is a fourth copy of the same defect in a different shape, and it is the failure mode most likely to survive this refactor unnoticed, because it reads as prose rather than as a table.

## Formatter constraint

CI runs the Markdown formatter over any changed Markdown, with a custom sentences-per-line plugin. A Go emitter writing tables into that page has to agree with it byte for byte, or CI fails on generated content.

The decision taken for this task is that emitter output must survive the formatter check unchanged, and a required check runs the emitter, then the formatter check, then a diff, so a disagreement fails loudly instead of silently. CI configuration is not changed.

If that proves unworkable in practice, the acceptable alternative is to exempt this one page from the Markdown pipeline, and the reason must be recorded in this task rather than left implicit in a config diff.

## Constraints

- The narrative sections are not generated. Sources and scope, the gap-classification scheme, compiler history including the record of a specific release transition, the genuine-gaps prose, and when-to-revisit stay hand-written, because they are this repository's own reasoning rather than a rendering of a table.
- The page is not fully generated, for the same reason.
- The rendered content is equivalent to today's page. A reader must not be able to tell which regions are generated except by their markers, and no construct row, verdict, gap class, or count is lost or reworded in the rendering.
- Generated regions are marked in a way that reads as a marker in raw Markdown and does not become a fourth section-level heading in the rendered page.
- Probe links continue to resolve to real directories, because the audit checks that and a generated link that no longer resolves is a regression.
- `audit.sh` is not reworked here. Its roster checks are expected to keep working against the rendered page, since the rendering is equivalent, and the checks that become redundant are removed in the next subtask rather than in this one.
- The tool stays a single nested module at its current path, and the corpus layout is unchanged.
- `gala` 0.84.1 and the go1.26 series stay the pinned toolchains, and the vendored runtime is not modified.

## Evidence required

Record the first regeneration as a diff summary, so the size of the change is visible.
Run the add-a-twin drill: add a twin, confirm the census check fails, regenerate, confirm the page and the check both go green with no hand-edited count. That drill is the whole point of the change, so it is required rather than optional.
