## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## Discovery

The asset is not a still image: it is an animated WebP (962x682, 12 full-canvas lossy frames, 11 x 600 ms plus 1 x 1200 ms, loop 0) plus a 36-byte EXIF chunk. The re-encode preserves the animation, because dropping it would be a visible behavior change.

## Tool and settings (reproducible)

Tools: Ubuntu noble `webp` 1.3.2-0.4build3, extracted locally without a system install (`apt-get download webp`, `dpkg-deb -x webp_1.3.2-0.4build3_amd64.deb webp-tools`).

1. Dump the source frames losslessly: `webp-tools/usr/bin/anim_dump -folder frames frontend/src/assets/demo/event.webp` produces `frames/dump_0000.png` through `frames/dump_0011.png`.
2. Re-encode as an animation with the original durations. Per-frame options precede each input, including `-d`:
   `webp-tools/usr/bin/img2webp -lossy -q 42 -m 6 -sharp_yuv -d 600 frames/dump_0000.png ... -lossy -q 42 -m 6 -sharp_yuv -d 1200 frames/dump_0011.png -o frontend/src/assets/demo/event.webp`
3. Verify structure with `webpinfo` and quality with `anim_diff event-original.webp frontend/src/assets/demo/event.webp -min_psnr 100`.

The re-encode drops the original 36-byte EXIF chunk; the landing view does not read it.

## Result

- Source asset: 417,756 bytes to 135,212 bytes (-282,544 B, -67.6%), still a 962x682 animated WebP with identical frame count, frame durations, and loop count.
- Emitted build asset: `event-DOj_qfok.webp` 417,756 bytes to `event-BMmDCAv1.webp` 135,212 bytes.
- Quality: `anim_diff` per-frame PSNR 37.99 to 38.84 dB, average 38.36 dB. Frames 0, 4, and 9 compared against the original at the rendered 700-800 px width and in 1:1 crops: no visible banding, blur, or color shift. Flat-area samples differ by at most about 5 levels (example: `srgba(209,237,223)` to `srgba(214,235,221)`).
