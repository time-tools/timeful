## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Why

`audit.sh` was written when the roster page was the source of truth for construct verdicts, and its checks reflect that: it parses the page's tables by section and by header name, then cross-checks the gap classification against the gap table, the gap identifiers against the spike record, and the mechanical-rewrite catalog against the construct roster in both directions.

After the previous subtask the page is a rendering. Three of those checks now compare generated text against the typed data it was generated from, which is a tautology dressed as a check: it can only fail if the emitter is non-deterministic, which a different check already covers.

The rest of the script is not tautological and is the part worth keeping. Probe directory integrity, orphan detection, unresolved link detection, and the table cell-count check are all statements about the filesystem and about the documents as documents, and none of them needs the typed table.

## Outcome

Consistency checks that need the typed data live in Go tests, where they are unit tests against a single source rather than text matching against a rendering. `audit.sh` keeps the checks that are genuinely cross-artifact and still needs neither a GALA nor a Go toolchain.

## Scope

- **Move to Go tests:** every detected family has a verdict row, every gap class is one of the closed set, every language or boundary row names a gap identifier, every gap identifier is reachable from such a row, and the mechanical-rewrite catalog agrees with the construct data in both directions. The last of these is the most valuable of the moved checks, because a substitutable family with no rule row, and a rule row claiming a family with no substitute, are the two ways the catalog drifts from the roster.
- **Keep in the script:** probe directory integrity, orphan probes, unresolved links, and the table cell-count check. The table check spans five enumerated documents, three of which are the skill's files, so it is a statement about the documents a reader compares against each other rather than about the roster's data.
- **Keep the gap-identifier cross-reference somewhere.** It is the one check that reaches across into a hand-written project document rather than into the typed data, so it does not become a tautology. Where it lands is a decision, and the reason is recorded. The spike record is not made generated in order to make this check easy.
- **Restate the toolchain-free claim.** The documents currently promise that the audit needs no GALA and no Go toolchain. After the split that is true of the script and not of the suite, and the promise has to be narrowed to what remains rather than left as an overstatement. An overstatement here is the same class of defect as the rest of this task: prose that asserts something the code no longer guarantees.
- **Drop nothing silently.** Every check that leaves the script is either reimplemented as a test or recorded as deliberately dropped with a reason.

## Constraints

- `audit.sh` stays read-only and modifies no file.
- The checks that remain in the script stay runnable without a GALA CLI and without a Go toolchain, because that property is what lets the script be run as a cheap gate.
- TASK-0338 adds a seventh check comparing every table row in the five enumerated documents against its own header. It is kept, and its presence is treated as a fixed input to this task rather than something to redesign.
- The script's own header comment enumerates its checks, and it stays accurate after the split.
- The probe corpus, its expectations, and its runner are not modified.
- The tool stays a single nested module at its current path.

## Evidence required

Record, check by check, where each of the script's existing checks ended up: moved to a named test, retained, or dropped with a reason. A check that cannot be placed is an open question, not a silent deletion.
