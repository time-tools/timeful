## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Why

TASK-0337 filed eight upstream issues on `martianoff/gala` and rewrote the local GALA documents so no file still claims something a reproduction has since refuted.
A review of that change set found the substance sound and the evidence real, but the edit pass left the documents themselves in a state that is not consistent: superseded text was left beside its replacement, four sentences and one table row were cut mid-clause, one document points readers at evidence that does not exist, and two new roster rows cite lines that are out of range or name the remedy instead of the defect.

The important operational fact is that every automated check in the project's Definition of Done passes on the broken state.
`audit.sh`, `go run ./inventory -check`, `npm run format:markdown:check`, `npm run test:markdown-rules` and root `npm run fmt:check` are all green, because none of them compares a table row against its header, none of them reads a sentence for terminal punctuation, and none of them resolves a prose pointer to a file.
The parent's acceptance criterion #8 requires the local documents to stay consistent, so that criterion is not satisfied by the state TASK-0337 was marked Done in, and this task closes the gap.

The eight filed issues and the #613 comment are outward-facing and already correct; this task changes no upstream state.

## What the review found

Mechanical damage from a replacement that was inserted without deleting the old text:

- `server/GALA.md`, the "What does not work" section: the bullets for a `swag` annotation on a handler, a method a handwritten sibling declares, `.Size()` on an inferred receiver, and a method call on a `:=` or `val` binding each carry their new body followed by the superseded body. In three of the four the two contradict each other, so the file currently denies the same finding twice.
- `server/GALA.md`: a bullet titled "Documentation comments." has an empty body and is immediately followed by "Documentation comments and every other comment."; the sentence "Generated Go contains no comments, so package comments live in handwritten `eventid/doc.go` and `services/providerconfig/doc.go`" survives twice, once correctly and once dangling as the last line of the unrelated #617/#620 bullet.
- `constructs.md`: the "Packages And Files" table has the row `| a declaration in a handwritten sibling |` with no cells and no closing pipe, in a six-column table. The row's Go, GALA, status, code and check cells are gone, and the prose beneath it still refers to that row.
- `constructs.md`: two sentences stop mid-clause, "The capture guard is boundary-specific" and "A package's imports are resolved as a unit but emitted per file", each having lost the clause that made it a sentence.

Claims that are not supported by what the repository contains:

- `gaps.md` states that the issue drafts and their diagnostics "live in the repository's Backlog task notes". They do not; the nine drafts are in a temporary directory outside the repository, and TASK-0337's notes hold only a summary table.
- `gaps.md` states that "Neither entry was filed", which reads as a claim that both the `const` entry and the comment entry were filed. Only the comment entry was, as #619; `const` is deliberately unfiled.
- The probe corpus does not pin the layout that upstream #616 was actually filed against. `blocked_bare_name_type_position` declares the colliding type in a handwritten `.go` sibling, while the filed issue, `gaps.md`, `SKILL.md`, `server/GALA.md`, `constructs.md` and the roster all describe the trigger as a sibling `.gala` file. Both layouts reproduce on the pinned compiler, and the corpus covers only one of them.
- The new roster row for `gala-type-go-sibling-method` cites `postgres/dailylogs.gala:43`; that file has 28 lines.
- The new roster row for `binding-method-receivers` cites `discord_bot/init.gala:81` as its representative occurrence, which is a `var` binding, and the same row names `var` as the only safe spelling; its parenthetical occurrence count is not derivable from the inventory and does not survive a hand count of the shape the row describes.
- `server/GALA.md` asserts that a block comment is captured rather than rejected, with no probe behind it; the corpus covers line comments only.
- Three changed documents call the zero-allocation substitute "measured", but nothing in the repository measures allocations. The vendored `go_interop` source and the #613 comment are what establish it.
- The probe note for `blocked_receiver_unwrap_val` names the wrong source keyword for the byte difference it describes.
- `run.sh` materializes the same `Response`/`newResponse` Go fixture in three separate case arms.
- `docs/gala-translation.md` appends a probe link to a table cell without the separator every other link in that cell uses.
- The parent's Implementation Notes still contain a section headed "Local documents that are now known to be wrong" whose text says the work is the remaining work of the task, above the section recording that it was done.
