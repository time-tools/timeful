## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Outcome

Remove the temporal-polyfill runtime dependency and all ponyfill import sites once every supported browser provides engine-native Temporal, so the app relies solely on native implementations. This follow-up was explicitly deferred from TASK-0116.

## Context

TASK-0116 upgrades to temporal-polyfill 1.x, which delegates to engine-native Temporal where available. As of Aug 2026, Firefox 139+, Chrome 144+, and Node 26 ship native Temporal; Safari/WebKit had not. Roughly 100 files under `frontend/src/` and `e2e/` use the ponyfill entrypoint (`import { Temporal } from "temporal-polyfill"` and `import type`).

## Preconditions and constraints

- Re-verify at execution that Safari/WebKit ships native Temporal enabled by default (release notes / caniuse) and that this satisfies the project's browser support expectation; do not drop the dependency while any supported browser still needs the JS polyfill.
- Value-semantics helpers stay centralized in `frontend/src/utils/temporalPrimitives.ts` per ADR-006.
- Update ADR-004 to record the removal and the resulting single native runtime model.
- No server-side changes.
