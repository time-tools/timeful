## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Outcome

Let the committed inventory tool answer "which GALA construct families does this one Go file contain, and what does the roster say about each?" so that a rewrite decision can be made before any GALA source is written.

`server/scripts/20260923_gala_translation_probes/inventory/main.go` already detects every construct family the roster classifies, and its `-check` mode diffs the roster's Inventory table against a fresh walk of the server module.
It cannot be pointed at a single file, and it never surfaces a verdict.
The roster's per-family `Gap class` and `Verdict` live in eleven-column Markdown tables that only the audit script can read, so a rewrite cannot be triaged mechanically and the first real attempt at a file is also the first time its blocking constructs are discovered.

TASK-0326 established this tool's posture: standard library only, nested module resolving the vendored runtime, read-only with respect to the roster, and a `-check` mode that fails on drift.
That posture stays.

## Requirements

- The tool accepts a single Go file and reports every construct family it contains, with an occurrence count and a `file:line` representative.
- Each reported family carries the `Gap class` and `Verdict` recorded in `docs/gala-translation.md`.
- Roster parsing is driven by the table header row rather than by fixed column positions, so adding or reordering a roster column does not silently mis-map a verdict.
- Roster parsing reads the construct roster section of the page and does not pick up rows from the other tables on the same page.
- The mode produces a single file-level verdict derived from the roster's own Decision ladder, so that a file whose families all have a rewrite path is distinguishable from one that must stay handwritten and from one that needs a split with a handwritten sibling.
- A file with no recognized construct family, an unreadable file, and a missing or restructured roster are each distinguishable in the output and in the exit status.
- Roster parsing and the file-level verdict rule are covered by committed unit tests in the corpus module, including a case that pins the section-bounding behaviour.
- The existing `-check` mode, the printed inventory table, and every pre-existing audit check behave exactly as they do today.

## Constraints

- Standard library only, matching the existing tool.
  No new dependency, and no change to the corpus `go.mod` module path or its `replace` onto the vendored runtime.
- The tool stays read-only with respect to the repository: it parses and reports, and never rewrites the roster or a server file.
- The file-level verdict is advisory.
  It does not gate anything, and the tool does not fail a run merely because a file is judged untranslatable.
- No construct family, verdict, gap class, or `GAP-n` entry is added to the roster by this task.
  A construct family the tool reports but the roster does not classify is a defect to surface, not a row to invent.
- Corpus commits stay limited to `.gala` sources, `expect`, `expected.out`, `go.mod`, `.gitignore`, `run.sh`, and the inventory tooling.
  Generated output stays gitignored by explicit path, so a newly committed test file must not be swallowed by those rules.
- The corpus `go.mod` declares an older Go language version than the server module; the tool and its tests must compile against it.

- The new mode observed failing on seeded drift and passing again, with both outputs, recorded in the task notes.
- The corpus run, the audit script, and `go run ./inventory -check`, all recorded in the task notes.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
## Plan

Baseline evidence: `go run ./inventory -check` reports `inventory check: doc matches (166 files)`; `audit.sh` reports 5 `ok` lines and `audit passed`.

### Implementation

1. Extract the per-file AST walk out of `compute` into an `inspector` struct with an injected `hit func(family string, line int)` callback, so the walk can be reused per file without changing `-check` or the printed table. `compute` keeps its existing `famSet` filter, class attribution, and hit order, so representatives and counts are unchanged.
2. Add a shared `addDefinedNonStruct` helper so the single-file mode builds the same per-directory `defined non-struct type` set the walk builds, which keeps `methods-on-defined-non-struct` detection consistent.
3. Add `-preflight <file>`: parse one Go file, run the shared walk, and report every family in `fams` with a count, a `file:line` representative, the roster `Gap class`, the roster `Verdict` verbatim, and a decision-ladder rung.
4. Roster parsing (`roster.go` or the same package): read the `## Construct roster` section only, and inside it read tables whose header row carries `Construct`, `Gap class`, and `Verdict`; map columns by header name, so column order changes are harmless. Parse `## Decision ladder` numbered rungs to learn the rung vocabulary instead of restating it.
5. File-level verdict: classify each family verdict cell mechanically (split marker, handwritten clause with/without a substitute, gap marker, else rewrite), then take the most conservative rung. Print the ladder verbatim from the roster and the chosen rung label verbatim.
6. Exit statuses: 0 advisory verdict, 2 unreadable/unparseable file, 3 missing or restructured roster, 4 no recognized construct family.
7. Unit tests in `inventory/main_test.go`: section bounding, header-driven column mapping, roster/ladder error cases, the verdict classifier, the file-level aggregation, and single-file detection.

### Documentation

Add a short paragraph to the `Inventory` section of `docs/gala-translation.md` describing the flag, the columns, and the exit codes, and add the new test file to the committed-file list in `Probe corpus`.

### Verification

`go test ./inventory`, `go run ./inventory -check`, `run.sh`, `audit.sh`, a seeded-drift fail/pass for the new mode, and `git check-ignore` on the new test file.

## What landed

- `docs/gala-translation.md`: a paragraph in the Inventory section describing the flag, the columns, the file-level verdict rule, and the exit codes, and the committed-file list now names the `inventory/` sources and tests.

## The file-level verdict rule

`classifyVerdict` reads one roster verdict cell, and the file takes the highest rung any family reaches, which is the ladder's own "choose the first rung that fits" read in reverse.

- a cell that asks for a split is a split;
- a cell that offers a substitute and also names a handwritten outcome is a split, because only part of the family rewrites;
- a cell whose only outcome is handwritten, or that names a gap, keeps the file handwritten;
- anything else is a rewrite.

Markers are the roster's own vocabulary (a direct form, an analog, a workaround, a gap, a split, a handwritten outcome) rather than a restated per-family verdict, and a negated clause such as "no handwritten sibling needed" is not a handwritten outcome. All 50 roster verdict cells classify; none needs a hand-written exception.

Spot checks against real files: `models/datetime.go` lands on rung 3, which is what the ladder's own rung-3 list says about it; `main.go` lands on rung 3; `logger/logger.go` and `observability/redact.go` land on rung 1; `appenv/appenv_port.go`, one of the committed split twins, lands on rung 2.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
## What landed

A `## Mechanical rewrites` section in `docs/gala-translation.md` with 38 rule rows and a 3-row no-rewrite index, and a new sixth check in `audit.sh` that gates the catalog against the roster in both directions.

The catalog is one row per rule, not per family: `| Go spelling | GALA spelling | Note | Probe | Construct families |`. The GALA spellings are the qualified `go_interop.`/`resource.` forms the committed twins already use, taken from the probe sources and confirmed against the vendored runtime, so every row is copyable rather than prose. 15 families carry a second row because their decision rule has genuinely different branches, such as a byte count against a character count or a Go container against a GALA collection, and each branch names its own probe.

The 22 families the roster classifies as `analog` or `workaround` are each named by at least one row, and no other family is named. The 28 families with no substitute are listed explicitly, grouped by gap class, so the absence is recorded rather than inferred. `close-calls` is the one substitutable family with no probe anywhere in the roster, so its row carries `—` in the Probe column, which is the roster's existing convention for a row with no scripted pin, and `copy-calls` and `interface{} type` carry notes saying the roster keeps them handwritten today.

## The gate

`audit.sh` extracts the construct roster section into one temporary file and both the pre-existing class lookup and the new catalog check read that file, so a table elsewhere on the page that repeats the same column names cannot influence either. The new check fails on a row that names a probe the corpus does not have, a substitutable family with no row, a row that claims a family the roster does not classify as substituted, a probe the roster does not record for a family the row covers, and a family missing from or misplaced in the no-rewrite index. It stays read-only and uses only bash, awk, sed, and grep.
