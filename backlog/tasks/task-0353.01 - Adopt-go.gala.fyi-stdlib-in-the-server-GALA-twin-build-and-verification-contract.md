## Context

TASK-0353 decides that the server's GALA twins adopt the published Go module `go.gala.fyi/stdlib` v0.87.1 instead of the runtime-free-only contract. The decision, the scratch evidence, and the module facts (plain Go module at v0.87.1, `go 1.24`, zero transitive requirements, vanity import resolving to `github.com/martianoff/gala-stdlib`) are recorded in `server/GALA.md` and TASK-0353's notes.

Today `server/go.mod` has no GALA runtime require, and `server/scripts/gala/verify.sh` rejects any generated twin that imports `martianoff/gala` or `go.gala.fyi/`. The pinned compiler is flake rev `cd2fdcb5` (gala 0.87.1, recorded in `server/GALA_COMPILER`), and it supports `gala transpile --stdlib-module go.gala.fyi/stdlib` (upstream PR #743).

## Outcome

The build and verification contract is switched to the adopted module. This task does not migrate any twin; it makes the contract legal so the migration task (TASK-0353.03) can land runtime-enabled twins.

## Required contract changes

- `server/go.mod`/`server/go.sum`: add the pinned `go.gala.fyi/stdlib` requirement and its hashes; keep `go mod tidy` a no-op and add no other dependency.
- `server/scripts/gala/verify.sh`: pass `--stdlib-module go.gala.fyi/stdlib` for every transpile; allow generated Go to import `go.gala.fyi/stdlib/...`; keep rejecting `martianoff/gala`; keep provenance, drift, gofmt, orphan, and build checks.
- Confirm all 22 committed twins regenerating under the flag are byte-identical to their committed files (runtime-free output should not change).
- `server/GALA.md` (contract, compiler section, registry regeneration command) and `server/README.md` move to the adopted policy; `martianoff/gala` stays banned.
- Validate and record the build paths: `go build ./...`; the canonical Compose sequence; the production image build and an isolated test container, including how the module is fetched when absent from a module cache and what that implies for CI caches and offline use.
- Format changed Markdown with `npm run format:markdown`.
