## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Replace mongo-driver types in the surviving PostgreSQL runtime with canonical types while preserving the current JSON wire format.

Convert server/models (Event, Response, User, CalendarEvent, SignUpBlock, SignUpResponse) and every live PostgreSQL path off primitive.ObjectID, primitive.DateTime, bson.M, and bson.A: server/routes/postgres_event_routes.go, server/routes/postgres_group.go, server/routes/event_timed_slots.go, server/routes/user.go, server/routes/folders.go, server/routes/guest_response_ownership.go, server/accounts, server/respondents, server/services/auth, server/services/calendar, server/services/listmonk, server/services/services.go, server/services/gcloud, server/slackbot, and server/discord_bot.
Delete Mongo-only models that no longer have runtime readers (Attendee, Folder, FolderEvent, EventResponse) and any dead deduction helpers.
Preserve the wire contract deliberately: 24-hex account and event identifiers, the zero-ObjectID guest sentinel surfaced to clients, RFC3339 datetime strings, millisecond-keyed manual availability maps, and the models.Event.MarshalJSON behavior, with regression tests for each.
Keep the account external-ID 24-hex format through a non-driver generator and keep the guest-name ObjectID-like validation.
Regenerate Swagger with the repo command and run npm run gen:api so server/docs and frontend/src/types/api.ts match.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

Dependency TASK-0199.09.01 is Done. Legacy events and `server/db` are gone; only the shared model types and PostgreSQL/tooling paths still hold driver types.

### Approach
1. Relocate the current BSON storage structs (`models.Event`, `Response`, `User`, `CalendarEvent`, `SignUpBlock`, `SignUpResponse`, `Attendee`, `Folder`, `FolderEvent`, plus the BSON-aware ID preference helper) into script-only `server/scripts/internal/legacybson` and repoint the preserved backfill scripts and their tests at it. 2. Create canonical `server/models` types with no driver dependency:

   - Convert `Event`, `Response`, `User`, `CalendarEvent`, `SignUpBlock`, `SignUpResponse`; drop `bson` tags; remove `Event.Attendees`/`Attendance` legacy shape only after confirming no runtime readers.
3. Convert runtime call sites: `accounts`, `respondents`, `routes` (postgres event/group/schedule, events helpers, user, respondent identity, guest ownership), `services` (auth, calendar, gcloud, listmonk, services), `slackbot`, `discord_bot`; replace `bson.M`/`bson.A` with `map[string]any`/`[]any`.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
TASK-0199.09.02 removes mongo-driver types from the surviving PostgreSQL runtime and replaces them with canonical `server/models` types while preserving the wire contract.

What changed:
- `server/models`: `ID` (24-hex with zero-ObjectID sentinel, JSON/Text/extended-JSON parity, `ParseID`, `NewID`), `DateTime` (RFC3339 values and integer millisecond map keys), and driver-free `Event`, `Response`, `User`, `CalendarEvent`, `SignUpBlock`, `SignUpResponse`, `Location`, and calendar option types. `ZeroID` is now an immutable `func ZeroID() ID`. `Event.MarshalJSON` keeps its legacy schedule-column suppression and always emits the Mongo-era `attendees` key as null so stored payloads and API shapes match HEAD; group reads replace it with the PostgreSQL attendee list.
- Runtime packages (`accounts`, `respondents`, `routes`, `services`, `slackbot`, `discord_bot`) now use the canonical types and `map[string]any`/`[]any` instead of `bson.M`/`bson.A`, with no non-test runtime driver imports.
- Mongo-only models (`Attendee`, `Folder`, `FolderEvent`, `EventResponse`) and dead deduction helpers are deleted; the backfill scripts use script-only `server/scripts/internal/legacybson` until TASK-0199.09.03 removes them.
- Boundary types in `frontend/src/types/{api,index,transport}.ts` were updated for the deleted models and the injected group attendee shape; Swagger and `frontend/src/types/api.ts` are regenerated.
