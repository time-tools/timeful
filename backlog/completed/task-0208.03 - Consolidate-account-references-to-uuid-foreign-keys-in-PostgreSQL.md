## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Account references are denormalized as TEXT columns keyed by platform_identities.external_user_id: account_user_id columns in event responses, attendees, signup responses, folders and folder events, availability groups, and daily user logs; postgres_events.owner_external_id; access_transfers.external_user_id; account_deletion_tombstones.external_user_id. Consolidate them onto native uuid columns referencing platform_identities.id, backfill existing rows once, then remove external_user_id and the legacy TEXT columns. event_visitor_identities.platform_identity_id and postgres_events.owner_platform_identity_id already exist and become the canonical references. Tombstones must survive identity deletion and therefore carry the uuid without a foreign key. This subtask ships with the backend boundary subtask.

Constraints:
- The backfill runs in a single guarded migration transaction, is idempotent on re-run, and refuses a destructive down migration without a reviewed data-preserving path.
- Drop platform_identities.external_user_id last, after every dependent column is consolidated and the mapping verified.
- Repository and service code must not query dropped columns; repository tests use the isolated test stack.
- Use native uuid columns and the existing uuidv7() defaults; do not add new TEXT identifier columns.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Research complete. The baseline still stores platform_identities.external_user_id (TEXT unique) and denormalizes it into postgres_events.owner_external_id, postgres_event_responses.account_user_id, event_signup_responses.account_user_id, event_attendees.account_user_id, folders/folder_events.account_user_id, access_transfers.external_user_id, daily_user_log_members.account_user_id, and account_deletion_tombstones.external_user_id. owner_platform_identity_id and event_visitor_identities.platform_identity_id already exist and are canonical.
2. Add a guarded migration that, in one transaction: adds platform_identity_id uuid columns (with FK to platform_identities(id) except tombstones), backfills each from the old external mapping, verifies zero unmapped rows, drops the legacy TEXT columns, and drops platform_identities.external_user_id last. Use IF NOT EXISTS so a re-run is a no-op and raise an exception if any referenced legacy value has no mapping.
3. Make the down migration refuse automatically, matching the baseline.
4. Rewrite repositories and services to read/write platform_identity_id: accounts/identities, calendar, dashboard, folders, attendees, dailylogs, transfers, repository, signup. No repository may query a dropped column.
5. Update route handlers and the accounts boundary so session, ownership, visitor authorization, folders, groups, transfers, daily logs, and deletion key on the platform identity UUID.
6. Update repository and route tests; add migration rehearsal coverage proving the backfill rewrites references, rejects unmapped rows, and is idempotent. Delete tests that assert TEXT account columns and replace them with platform identity assertions.
7. Run go build ./..., go vet ./..., and the isolated compose.test.yaml backend suite including account repository packages.

Evidence to capture: migration up/down behavior, backfill counts, isolated suite output.
