## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The Go boundary currently mints a 24-hex value on sign-in (models.NewID().Hex()) and passes it through platform_identities.external_user_id; the sign-in session and models.User.Id carry it. Change the runtime so the platform identity UUID (platform_identities.id, generated by the uuidv7() default) is the account identifier: FindOrCreatePlatformIdentity no longer accepts or stores an external id, session userId stores the uuid, account resolution and ownership checks key on platform_identity_id, and models.ID no longer represents account identity. Guest and unowned zero semantics must survive the change. Swagger and the generated frontend API types are regenerated. This subtask ships together with the schema consolidation subtask; no request path may accept the legacy 24-hex account id.

Constraints:
- No compatibility lookup: after the cutover, an old 24-hex session value resolves to no account.
- Keep boundary and transport types separate from internal types per the frontend ADRs; keep transport decoding at explicit boundaries.
- Preserve the existing guest and unowned zero-identity behavior and the event and signup wire fields unrelated to account identity.
- Follow the backend conventions in AGENTS.md, including Swagger regeneration (swag v1.16.6) and npm run gen:api.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Research complete. Runtime account identity is currently a minted 24-hex value passed through platform_identities.external_user_id: accounts.ResolveForSignIn mints models.NewID().Hex(), FindOrCreateAccount/FindOrCreateAccountByEmail take it, the session stores it, every repository resolves platform_identities by it, and models.ID backs the _id/ownerId/userId wire fields with the 24-hex zero sentinel.
2. Replace the 24-hex models.ID with a canonical lowercase hyphenated RFC 9562 UUID type and the all-zero UUID zero sentinel; delete models.NewID/ParseID/ID and update Event, Response, User, and sign-up block fields. Signup block _id becomes an opaque client string the server ignores, so no account path parses 24-hex.
3. Migration and repository consolidation ship as TASK-0208.03 in the same change set (external_user_id is NOT NULL and must be dropped to satisfy this task).
4. Replace FindOrCreatePlatformIdentity with a resolve-only platform identity lookup for session paths and create the identity only inside email sign-in; no runtime path accepts or stores an external id.
5. Store account.PlatformIdentityID in the session, resolve accounts by platform identity UUID, and key visitor ownership, event ownership, transfers, folders, groups, daily logs, and deletion on it.
6. Update route contracts so wire account fields carry the platform identity UUID and guest/unowned fields carry the all-zero UUID; keep unrelated event and signup wire fields.
7. Add regression tests for first and repeat sign-in, an invalid legacy 24-hex session, guest zero identity, and account-keyed authorization; update existing tests.
8. Regenerate Swagger with swag v1.16.6 and frontend/src/types/api.ts with npm run gen:api; run go build ./..., go vet ./..., the isolated compose.test.yaml suite, and the frontend required checks.

## Final Summary
