## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Remove the MongoDB runtime, driver dependency, configuration, collections, and one-off tooling after the retained-data cutover, the historical daily-log backfill, and the core-record cutover have passed.

This is an umbrella task; delivery is split into subtasks:
- TASK-0199.09.01 removes the legacy MongoDB event runtime and the server/db package.
- TASK-0199.09.02 replaces mongo-driver types in the surviving PostgreSQL runtime.
- TASK-0199.09.03 retires the migration tooling and drops the mongo driver from go.mod/go.sum.
- TASK-0199.09.04 removes MongoDB Compose, environment, CI, and E2E configuration.
- TASK-0199.09.05 updates documentation, requirements, glossary, and the retirement record.
- TASK-0199.09.06 verifies PostgreSQL-only startup, suites, and E2E and records the umbrella evidence.
- TASK-0199.09.07 removes the historical migration documentation, prunes the PostgreSQL runbooks, and finalizes this task.

Legacy noncanonical events and identifiers are intentionally dropped, and the frontend m_ legacy link handling is removed with the runtime.
TASK-0199.10 is a hard predecessor because it reads MongoDB dailyuserlogs through the driver that this task removes.
Deleting the migration tooling and representative fixtures is allowed only after the TASK-0199.10 backfill and the live-cutover evidence are recorded, because removal is irreversible.
Do not start any subtask until TASK-0199.10 is Done.

## Decomposition

TASK-0199.09 is delivered as seven subtasks, gated on TASK-0199.10:
1. TASK-0199.09.01 - Remove legacy MongoDB event runtime and server/db package (depends on TASK-0199.10).
2. TASK-0199.09.02 - Replace mongo-driver types in surviving PostgreSQL runtime (depends on .01).
3. TASK-0199.09.03 - Retire MongoDB migration tooling and drop the mongo driver (depends on .02 and TASK-0199.10).
4. TASK-0199.09.04 - Remove MongoDB Compose, environment, CI, and E2E configuration (depends on .01 and .03).
5. TASK-0199.09.05 - Update documentation, requirements, and glossary for final MongoDB retirement (depends on .04).
6. TASK-0199.09.06 - Verify PostgreSQL-only startup, suites, and E2E and record the umbrella evidence (depends on .03, .04, .05).
7. TASK-0199.09.07 - Remove historical migration documentation, prune the PostgreSQL runbooks, and finalize this task (depends on .06).

### Ordering rationale
- TASK-0199.10 must complete first because it reads MongoDB dailyuserlogs and needs the driver and retained source intact.
- Legacy Mongo readers must be deleted before model and transport types can move off driver types, because the Mongo handlers BSON-decode the models.
- The driver can be dropped only after every runtime and script package stops importing it.
- Configuration, documentation, and final verification follow the runtime removal.
- The historical migration documentation is removed only after TASK-0199.09.06 verifies the PostgreSQL-only system, so the retirement record stays intact through verification.

### Decisions
- Legacy noncanonical events and identifiers are dropped; no read-only Mongo compatibility path remains.
- Migration tooling and representative fixtures are deleted after TASK-0199.10 and the live-cutover evidence are recorded; the removal is irreversible.
- The executed-migration documents (`postgres-core-migration-contracts.md`, `postgres-core-migration-runbook.md`, `postgres-retained-data-contracts.md`) are removed after verification, preserving their durable rules in a successor contract; completed Backlog records and handoffs remain history.

### Key risks
- JSON wire format: 24-hex identifiers, the zero-ObjectID guest sentinel, RFC3339 datetimes, millisecond availability map keys, and models.Event.MarshalJSON must be preserved and covered by regression tests.
- Pre-removal rollback boundaries must be recorded before collections and tooling are deleted.
- The backup/restore rehearsal evidence is already recorded in TASK-0190.08 and the runbooks; capture it in the retirement record before deleting the tooling.
- Removing the migration documents must not drop durable behavior rules or leave dangling links.

### Working defaults
- Follow AGENTS.md and the repository requirement, terminology, and Markdown authoring rules.
- Run the isolated Compose backend suite and the required frontend and e2e checks for each implementation subtask.
