## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Remove the last retained MongoDB account usage and retire the dormant friend-request storage.

Delete the `friendrequests` model, accessor helpers, collection variable, and account-deletion coverage instead of migrating it.
Remove the retained MongoDB `users` document reads and writes: the `GetUserById` MongoDB fallback, `EnsureIntegrationDocument`, the account/integration overlay in middleware, and `UpdateUserIntegrationFields` once calendar, OTP, and daily-log data are PostgreSQL-authoritative.
Collapse account deletion so it no longer depends on a MongoDB cleanup step.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Friend-request storage is retired: deleted `server/models/friend_request.go`, `server/db/utils.go`, the `FriendRequestsCollection` variable and assignment, the unused `FriendRequestNotFound`/`UserNotFriends` error codes, and all friend-request fixtures from route tests. No runtime or test code references remain; only one-off historical scripts and generated docs mention the old collection name.

The retained MongoDB account document is no longer read or written at runtime. `db.GetUserById`/`db.GetUserByEmail` now build the internal user shape from the authoritative account through the new `db.AccountUser`, and `MongoUserById`, `MongoUserByEmail`, `EnsureIntegrationUser`, `UpdateUserIntegrationFields`, `RemoveUserCalendarAccount`, `MergeAccountProfile`, and the Mongo decode helpers are gone. `accounts.Resolve`, `ResolveForSignIn`, and `IsNewUser` no longer adopt legacy documents, `EnsureIntegrationDocument` and `accountFromLegacy` are deleted, and `respondent_identity.go` no longer guards on `db.UsersCollection`. `UsersCollection` remains defined only for the one-off scripts handled by TASK-0199.09.

Account deletion is PostgreSQL-only: `server/db/account_deletion.go` is deleted, `accounts.Deleter` exposes only the PostgreSQL step, and the delete-account comment and Swagger description no longer claim MongoDB or friend-request cleanup. Retained legacy records are now recovery source and are never modified by deletion.

Tests were moved to PostgreSQL authority: `db/users_test.go` and `accounts/accounts_test.go` were rewritten, route suites seed PostgreSQL accounts instead of Mongo users, and new regression coverage proves a retained document is never served and deletion leaves the retained store untouched. E2E helpers (`account-auth.ts`, the access-transfer `seedAccount`) stop seeding Mongo users.

Docs updated: `postgres-core-migration-contracts.md` (account lookup behavior, friend-request rows, retained references), `postgres-anonymous-event-compatibility.md`, and `FR-123`. Swagger (`docs.go`, `swagger.json`, `swagger.yaml`) and `frontend/src/types/api.ts` were regenerated from the changed annotation, and changed Markdown was formatted.

Evidence: `go build ./...` and `go vet ./...` clean; the isolated compose `server-route-test` suite passes every package including `db`, `accounts`, `postgres`, and `routes`; frontend lint, fmt:check, typecheck, build, and unit (1089 tests) pass; e2e lint, fmt:check, and typecheck are clean; focused e2e passes on `account-deletion.spec.ts` (chromium, 2 tests), the guest access-transfer journey (firefox), and the Google calendar connection journey (firefox); `npm run format:markdown:check` is clean. `graphify update .` was run.

Dependency note: TASK-0199.07 remains marked To Do, but all three of its subtasks (0199.07.01-0199.07.03) are Done and their commits are present, so its deliverable was in place before this task started.
