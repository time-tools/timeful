## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add the resumable, ledger-based backfill for existing historical daily user logs, deferred from TASK-0199.05 per the retained-data contract.

Read every retained MongoDB `dailyuserlogs` document and copy it into `daily_user_logs` (fresh identity keyed by the account-local date) and `daily_user_log_members` (one row per `userIds` entry, first-seen order preserved).
Resolve each membership owner through `platform_identities.external_user_id`; quarantine a log whose owner has no PostgreSQL account row with the `missing-owner-account` reason code and migrate nothing for it.
Record each migrated unit in the existing `migration_ledger` keyed by `(kind, legacy_id)` with the fresh `daily_user_logs.id`, and leave the MongoDB source documents unmodified.
Provide reconciliation for counts, date bucketing, and first-seen order, plus interruption and rerun coverage against representative fixtures with overlapping and empty days.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Added the one-off backfill at `server/scripts/20260911_mongo_dailyuserlogs_to_postgres/` following the retained calendar backfill pattern.

Key decisions:
- The migration unit is one retained `dailyuserlogs` document. A log with any member that does not resolve to a PostgreSQL account (missing platform identity or account row) quarantines the whole unit as `missing-owner-account` and writes no target rows, matching the task description and AC2.
- Duplicate legacy dates cannot survive in PostgreSQL because `daily_user_logs.log_date` is unique, so units sharing a date upsert one fresh log identity and append membership in `_id` order with max-position+1 and `ON CONFLICT DO NOTHING`. This preserves first-seen order across overlapping documents.
- Reconciliation is source-vs-target over the ledger rather than target-only counts, because overlapping dates make target log count differ from ledger unit count. It compares member sequences per date and flags source logs that are neither migrated nor quarantined.
- No runtime repository method was added; the backfill writes SQL inside its own transaction, matching the events backfill.
<!-- SECTION:NOTES:END -->
