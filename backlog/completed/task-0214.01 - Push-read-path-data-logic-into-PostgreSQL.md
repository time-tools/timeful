## Description

# Goal

Push read-path data logic that currently loops in Go into set-based PostgreSQL repository queries.

# Scope

- `server/routes/analytics.go:137-154` and `:224-237`: replace the per-day `CountDistinctMonthlyActiveEventCreators*` loop with one day-spine query per endpoint (`generate_series`/`unnest` over dates; no reporting table exists); preserve ascending day order, the exact `23:59:59` client-offset upper bound, and the per-day half-open `[day-30d, day)` lookback.
- Decide and document analytics error handling: the current loop skips a failed day and returns a short 200 array, which one statement cannot reproduce; the recommended behavior is to fail the request with 500.
- `server/postgres/dailylogs.go:133-160` (`padDailyUserLogs` at 133-147 and `insertDailyUserLog` at 149-160): return padded days from a `generate_series` day spine joined to `daily_user_logs`; bind UTC-normalized date bounds instead of casting a `timestamptz` in SQL; keep existing logs with `log_date >= startDate` even beyond the spine; preserve newest-first order and non-nil empty member slices.
- Prefer folding `ListDailyUserLogs` and padding into one `ListActiveUserDays` query (day spine LEFT JOIN logs LEFT JOIN members LEFT JOIN accounts) instead of padding in SQL and then reading again.
- `server/routes/postgres_event_routes.go:279-291` and `:228`: batch authorization so `visitor.controls` does not run one EXISTS per response; preserve the `controls` precedence (granted visitor, acting visitor, empty platform identity) and blind-availability filtering.
- `server/routes/respondent_identity.go:55-88`: replace the per-response `accounts.UserByPlatformIdentityID` lookup with a batched repository read or read model, then pass the account map into `populateSignUpResponsePayloadIdentity`; do not add account columns to the canonical `postgres.SignupResponse` shape shared by write paths; preserve the missing-account fallback and Go-side sanitization, and document the transient-error behavior change.
- `server/routes/postgres_group.go:129-153`: this runs once per event read, not per response; prefer reusing the responses already loaded by `postgresResponses` or add one repository EXISTS method backed by `postgres_response_visitor_idx`.
- `server/routes/postgres_group.go:81-95`: defer the case-insensitive attendee email check to TASK-0214.04, which adds the supporting `event_attendees lower(email)` index; attendees are already loaded in memory and no schema change is allowed here.
- `server/postgres/calendar.go:113-134`: keep the Go-side canonical UUID guard; merge identity liveness with `EXISTS`/`INSERT ... SELECT ... FROM platform_identities` and map zero rows to `pgx.ErrNoRows` only where the merged statement is equivalent; do not blanket-remove `requirePlatformIdentityID`, because inserts/upserts and list reads change missing-identity behavior.
- `server/postgres/transfers.go:78-84`: fetch the transfer source credential in one query by primary key; the `event_visitor_identity_id` re-filter and `id::text` cast are redundant; keep `GetEventVisitorCredential` for the credential-cookie path.
- `server/postgres/identities.go:115-121` (`LockEvent` lock-then-reread, assigned to this subtask by the parent audit): either merge into one `SELECT ... FOR UPDATE` or record the deferral.

# Constraints

- SQL stays in `server/postgres/` as repository methods; routes must not issue SQL directly.
- Preserve wire shapes, ordering, and authorization semantics exactly, except the explicitly documented analytics error-handling decision.
- No schema changes in this subtask; the attendee case-insensitive email index belongs to TASK-0214.04.
- Reporting output keeps non-nil empty slices so JSON stays `[]`.
- Corrections to this task must go through Backlog tools, not direct edits to the generated Markdown.

## Findings

## Summary

Pushed the remaining read-path data logic into set-based PostgreSQL repository methods and batched the per-row route reads.

### Changes

- **Analytics** (`postgres/analytics.go`, `routes/analytics.go`): replaced the per-day Go loop with one `unnest($1::timestamptz[]) WITH ORDINALITY` day-spine query per endpoint. The route builds the ascending `23:59:59` client-offset day ends (`analyticsDayEnds`); each day keeps its `[day-30d, day)` half-open window and zero-count spine entries. A query failure now fails the whole request with 500 instead of returning a short 200 array.
- **Daily user logs** (`postgres/dailylogs.go`): `ListActiveUserDays` is one `generate_series` day-spine query (UNION of stored logs `>= startDate`), with UTC-normalized date binds, newest-first order, existing logs beyond the spine retained, and non-nil empty member slices. Removed `ListDailyUserLogs`, `padDailyUserLogs`, and `insertDailyUserLog`.
- **Batched authorization** (`routes/postgres_identity.go`, `routes/postgres_event_routes.go`, `postgres/identities.go`): `postgresResponses` and `postgresSignupResponses` now use `controlsBatch` plus one `EventVisitorIdentitiesBelongingToAccount` read, preserving granted-visitor, acting-visitor, then account-association precedence and blind filtering.
- **Signup account profiles** (`postgres/accounts.go`, `routes/respondent_identity.go`): one `ListAccountsByPlatformIdentityIDs` read feeds `populateSignUpResponsePayloadIdentity`. Missing accounts keep the stored-response fallback and Go-side sanitization; a failed batch read logs and falls back for every account response, documented in code and notes.
- **Group viewer check** (`routes/postgres_group.go`, `postgres/identities.go`): `EventVisitorHasResponse` EXISTS backed by `postgres_response_visitor_idx`; the case-insensitive attendee email check is deferred to TASK-0214.04.
- **Calendar** (`postgres/calendar.go`): retained the Go-side canonical-UUID guard (`guardPlatformIdentityID`), merged identity liveness into `INSERT ... SELECT ... FROM platform_identities` for creates/upserts/preferences, and kept `requirePlatformIdentityID` only for list/delete paths where an empty result is ambiguous, so `pgx.ErrNoRows` semantics are preserved.
- **Transfers** (`postgres/transfers.go`): `GetTransferSourceCredential` reads the credential by primary key in one query.
- **LockEvent** (`postgres/identities.go`, `postgres/repository.go`): merged to one `SELECT ... FOR UPDATE`, sharing `eventColumns`/`scanEvent` with `getEvent`.
