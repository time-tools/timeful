## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Phase 3 of TASK-0224. Remove the legacy compatibility surface that TASK-0224.01 closed and TASK-0224.04's recreate-and-verify results prove is no longer needed. Candidate classes, each removed only from the recreate decision plus writer-path analysis (TASK-0224.01 reported no live legacy rows, and recreated databases start from the baseline):
- guest_id, canonical_guest_name, guest_edit_policy, guest_ownership_mode, and guest_edit_token compatibility columns and their repository read/write plumbing. Note that canonical_guest_name and respondent_kind still have current writers, so their removal needs a behavior decision, not only row counts.
- NULL respondent_kind coercion and inference, with the column made explicitly NOT NULL if no writer produces NULL.

Constraints: keep PostgreSQL access in server/postgres/; preserve JSONB payload round-trip, blind-availability privacy, EVCC authorization precedence, guest-name normalization, and credential encryption; update server/docs/postgres-data-boundaries.md and server/docs/postgres-anonymous-event-compatibility.md where they describe retired behavior. Do not remove read compatibility that a rollback to the prior server release depends on (docs/environments.md requires incremental migrations to stay compatible with the prior PostgreSQL-aware release); record the retained window. ## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Implementation plan (researched 2026-09-14, depends on TASK-0224.02/0224.04 which are Done; all in-scope databases are baseline-created).

Decision basis
- Writer-path analysis on HEAD 63473f5e:
  - postgres_event_responses guest columns: guest_id / guest_edit_policy / guest_ownership_mode / guest_edit_token have no writers; canonical_guest_name has one write-only writer in the group route (nothing reads it; GetResponseByGuestName is dead). Guest names that matter are normalized in Go and persisted in the JSONB payload (generic responses) or in event_signup_responses.canonical_guest_name (live, with the identity CHECK and unique index).
  - respondent_kind on postgres_event_responses is nullable but every writer sets 'account' or 'guest'; reconstruction rejects NULL. NULL rows can only predate the baseline, and recreated databases hold none.
  - ActualCalendarAccountMapKey / legacyKey retry paths exist for legacy mixed-case map keys. Recreated databases contain only canonical keys, and every writer computes keys through GetCalendarAccountKey.
- Rollback window: docs/environments.md:352 requires incremental migrations to stay compatible with the prior PostgreSQL-aware release. The prior release's repository.go names all five guest columns in SELECT/INSERT/UPDATE, so dropping them would break a rollback. They are retained physically with the recorded reason "prior-release rollback window"; the new server stops reading/writing them, and a later release after the window closes can drop them.

Steps
1. New forward-only goose migration 20260915000000_postgres_event_responses_respondent_kind_not_null.sql: Up SET NOT NULL on respondent_kind; Down DROP NOT NULL. No column drops (rollback window).
2. New server/postgres/respondent_kind_test.go: temp-harness test that the chain ends NOT NULL (attnotnull, NULL insert rejected with 23502, invalid kind still 23514) and a Down test that restores nullable behavior.
3. server/postgres/types.go: remove GuestID, CanonicalGuestName, GuestEditPolicy, GuestOwnershipMode, GuestEditToken from Response.
4. server/postgres/repository.go: simplify CreateResponse/getResponse/listResponsesQuery/UpdateResponse to the live columns; drop COALESCE(respondent_kind, ''); remove dead GetResponseByGuestID and GetResponseByGuestName. Add a test that the retained columns stay NULL through the new writer path.
5. server/routes/postgres_group.go: stop writing stored.CanonicalGuestName (rename, create-account, applyPostgresGroupGuestName); guest names stay in the payload value.Name. Update postgres_group_response_test.go assertions from the column to the payload name.
6. server/postgres/attendees_test.go: drop the dead CanonicalGuestName seed; baseline_schema_test.go keeps the retained-columns insert with a comment tying it to the rollback window.
7. Mixed-case calendar keys: remove utils.ActualCalendarAccountMapKey and dead utils.GetPrimaryAccountKey; use utils.GetCalendarAccountKey in services/auth/auth.go, services/contacts/contacts.go, routes/auth.go (drop legacyKey lookup/delete), and routes/user.go add/remove/toggle paths.
8. Docs: server/docs/postgres-data-boundaries.md (canonical key lookup only) and server/docs/postgres-event-api-contract.md (canonical_guest_name scoped to signup responses; respondent_kind NOT NULL; retained guest columns recorded). The task names postgres-anonymous-event-compatibility.md, which TASK-0215 renamed to postgres-event-api-contract.md.
9. Retained with recorded reason: five guest columns (rollback window), signup-instant decoding and group manualAvailability dual decoding (not auditable from stored rows, per TASK-0224.01), models.Response guest wire fields (no API/wire change allowed), normalizeSignupResponseIdentity empty-kind inference for the already-NOT NULL signup table.
10. Verify: gofmt/go build/go vet on the host if available; isolated backend suite via compose.test.yaml; targeted Firefox desktop e2e for event, response, signup, and calendar flows; format:markdown check.

Risks: the SET NOT NULL migration fails loudly if a database holds a NULL kind (none do by construction); canonical-key-only lookup assumes no non-canonical key survives (proven by recreate plus single canonical writer path).
