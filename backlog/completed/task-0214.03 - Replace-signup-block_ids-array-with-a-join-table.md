## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
# Goal

Replace the `event_signup_responses.block_ids TEXT[]` document-array shape with a relational join table and set-based capacity and membership logic.

# Scope

- Add a goose migration in `server/migrations/` creating `event_signup_response_blocks` with foreign keys to `event_signup_responses` and `event_signup_blocks`, a unique constraint on `(response_id, block_id)`, a `position` column that preserves the response's claimed-block order, and an index that supports grouped capacity counts and block cascades (for example `(block_id, response_id)`).
- Backfill the new table from existing `block_ids` values in array order (using `WITH ORDINALITY` for `position`), deduplicating entries and skipping values that do not name a same-event block, then drop `event_signup_responses.block_ids`.
- Rewrite the response membership paths in `server/postgres/signup.go`: `CreateSignupResponse`, `UpdateSignupResponse`, `GetSignupResponseByPublicID`, `ListSignupResponses`, `signupResponseColumns`, and `scanSignupResponse` read and write the join table, and every read aggregates memberships back into `BlockIDs` ordered by `position`.
- Rewrite `server/postgres/signup.go:350-398` `reserveSignupCapacity` to use a grouped JOIN against the join table with the excluded response applied in the query, and to still report `ErrSignupBlockNotFound` for any requested block that is missing or belongs to another event.
- Rewrite `server/postgres/signup.go:111-189` `ReplaceSignupBlocks` to use set-based upsert and delete statements, preserving `pgx.ErrNoRows` when a supplied block ID does not belong to the event.
- Keep the trimming, empty removal, and first-seen dedupe in `normalizeSignupBlockIDs`; the unique constraint is the backstop.

# Constraints

- The capacity check must remain inside the transaction that holds the event row lock.
- Preserve `ErrSignupBlockNotFound` (400 `signup-block-not-found`) and `ErrSignupCapacityExceeded` (409 `signup-slot-full`) semantics, including for non-canonical or foreign block identifiers; invalid UUID text must not surface as a SQL cast error.
- Preserve the wire `BlockIDs` order observed by clients. A position column is required, not optional.
- Specify `ON DELETE CASCADE` on both join-table foreign keys. Decide and record whether removing a block still bumps `event_signup_responses.updated_at`, which the current detach path does and a cascade alone does not.
- Typed UUID binds and the remaining `public_id::text` casts in `server/postgres/signup.go` belong to TASK-0214.04, which depends on this task; keep the existing cast behavior in statements this task does not rewrite.
- The baseline migration is immutable; add a new migration instead.
- The new migration must stay compatible with the temp-table migration harness at `server/postgres/migration_helpers_test.go:57-59`.

# Verification

- Apply migrations against the isolated test stack and run the repository and route signup test suites under `compose.test.yaml`.
- Add migration and repository regression tests for capacity, duplicate and empty block IDs, foreign block IDs, and multi-block ordering round-trip.
- Update the existing tests that read `event_signup_responses.block_ids` directly, such as `server/postgres/signup_test.go:355`.

## Implementation Plan

# Implementation plan

## Findings

- `event_signup_responses.block_ids TEXT[]` is the only membership store (`server/migrations/20260912000000_baseline_schema.sql:247`); capacity is a per-block count with `$2 = ANY(block_ids)` (`server/postgres/signup.go:350-398`), and `ReplaceSignupBlocks` loops per block (`signup.go:111-189`).
- Reads and writes share one `signupResponseColumns`/`scanSignupResponse` pair (`signup.go:70-79`) used by Create, Update, Get, and List.
- The temp-table migration harness executes every file's Up part (`server/postgres/migration_helpers_test.go:57-59`), so plain `CREATE TABLE`, `CREATE INDEX`, and `ALTER TABLE ... DROP COLUMN` stay compatible.
- `ReplaceSignupBlocks` currently detaches removed blocks and bumps `event_signup_responses.updated_at`; a join-table cascade does not, so the rewrite must preserve the bump explicitly and record that decision.
- `ReplaceSignupBlocks` must keep `pgx.ErrNoRows` for supplied IDs that do not name a same-event block, so the set-based upsert cannot insert rows for unknown IDs; the insert filters through an event-scoped `EXISTS` and compares affected rows with the deduped input count.
- Duplicate non-empty block IDs would raise PostgreSQL `21000` under `ON CONFLICT DO UPDATE`, as in TASK-0214.02, so dedupe on the last occurrence in Go before binding.
- Client block IDs may be non-canonical UUID text, so membership and capacity comparisons keep `id::text = ANY(...)` and never cast client text to uuid; typed binds stay with TASK-0214.04.

## Steps

1. Add `server/migrations/20260913000000_signup_response_blocks.sql`: table with both `ON DELETE CASCADE` foreign keys, `UNIQUE (response_id, block_id)`, `NOT NULL position`, and a `(block_id, response_id)` index; backfill with `DISTINCT ON (response_id, block_id)` over `unnest(block_ids) WITH ORDINALITY` joined to same-event blocks; drop `block_ids`; reversible Down that rebuilds the array ordered by position.
2. `server/postgres/signup.go`: split the scalar response columns from the aggregated membership expression; aggregate `block_id::text` ordered by position; rewrite Create and Update to write memberships set-based and re-read the full row; rewrite Get and List; leave Delete to the FK cascade.
3. Rewrite `reserveSignupCapacity` as one grouped `LEFT JOIN event_signup_response_blocks` query with the excluded response applied in the join, keep the text comparison so non-canonical IDs cannot raise `22P02`, and keep the missing-block length check mapping to `ErrSignupBlockNotFound`.
4. Rewrite `ReplaceSignupBlocks`: capacity validation and last-occurrence dedupe in Go; explicit `updated_at` bump for responses losing a removed block; set-based `DELETE` for removed blocks; one `INSERT ... ON CONFLICT (id) DO UPDATE ... SELECT ... WHERE EXISTS (...)` upsert with the affected-row count checked for `pgx.ErrNoRows`.
5. Tests: update `server/postgres/signup_test.go:355` to count through the join table; add multi-block ordering round-trip, duplicate/empty/foreign/non-canonical block ID coverage, capacity through the join table, and a backfill test that applies the baseline, seeds legacy `block_ids`, then applies the new migration and checks position order, dedupe, and dangling-ID skipping.
6. Run the isolated backend suite under `compose.test.yaml`, `gofmt`, `go vet ./...`, and `graphify update .`; record per-criterion evidence and finalize.

## Final Summary

## Summary

Replaced `event_signup_responses.block_ids TEXT[]` with the `event_signup_response_blocks` join table and moved membership and capacity logic to set-based SQL. A pre-commit review then tightened the capacity invariant, membership-write backstop, aggregate ordering, and rollback coverage.

### Changes

- **Migration**: `server/migrations/20260913000000_signup_response_blocks.sql` creates the join table with `ON DELETE CASCADE` foreign keys on both sides, `UNIQUE (response_id, block_id)`, `NOT NULL position`, a `(block_id, response_id)` index for grouped capacity counts, and a `(response_id, position, block_id)` index for the ordered membership aggregate; backfills legacy `block_ids` with `DISTINCT ON (response_id, block_id)` over `unnest(block_ids) WITH ORDINALITY` (array order, first-occurrence dedupe, same-event match only); drops `block_ids`; the Down rebuilds the array in position order.
- **Membership paths** (`server/postgres/signup.go`): Create and Update replace memberships with one delete plus one set-based insert and re-read the response, so `BlockIDs` comes back in stored `position, block_id` order; the insert's affected-row count maps a dropped identity to `ErrSignupBlockNotFound` as a backstop to the capacity pre-check; Get and List select the correlated aggregate; Delete relies on the FK cascade.
- **Capacity**: `reserveSignupCapacity` is one grouped `LEFT JOIN` over the join table with the excluded response applied in the join and memberships restricted to responses of the same event, so a cross-event membership cannot consume a seat; missing, foreign, nonexistent, and non-canonical block identifiers still return `ErrSignupBlockNotFound` because the comparison stays text-based.
- **ReplaceSignupBlocks**: one set-based delete plus one `INSERT ... ON CONFLICT (id) DO UPDATE ... SELECT` whose affected-row count maps to `pgx.ErrNoRows`; repeated non-empty supplied IDs collapse to their last occurrence to avoid PostgreSQL `21000`; removing a claimed block still bumps the affected responses' `updated_at` (recorded decision).
