## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Review of the shipped TASK-0208.02/.03 change set found regressions that block the cutover. The schema consolidation migration backfills uuid columns but never rewrites the stored JSONB payloads, and the strict models.UUID decoder rejects the retired 24-hex values that pre-cutover rows still contain, so legacy events and responses fail to load. Additional boundary bugs let unvalidated session values and client signup-block identities reach uuid columns, producing PostgreSQL errors instead of the documented no-account behavior.

Desired outcome: every pre-cutover row remains readable after the migration, every account-identity boundary validates or resolves the platform identity UUID before it reaches PostgreSQL, and the recorded behavior claims match the implementation.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Chose the migration rewrite over a tolerant UUID decode so ADR-021's canonical-only wire contract stays intact and stored payloads become readable at rest.

Transfer creation now mirrors the other session boundaries: resolve the platform identity, and treat a retired or deleted value as anonymous rather than a database error.

Group edits leave a legacy account response's missing identity as NULL rather than inventing one; the signed-out credential holder keeps edit authority through the EVCC.

Signup block _id validation lives at the route decode boundary (canonicalSignupBlockID) so the repository keeps treating stored UUIDs as the only real identities.

The migration rehearsal now seeds realistic legacy event and response payloads and asserts both decode after the rewrite; gofmt was applied to that test file, which exposed alignment drift inherited from the original cutover.

Recorded the two stale e2e SQL queries as a handoff comment on TASK-0208.05 instead of expanding this task's scope.
