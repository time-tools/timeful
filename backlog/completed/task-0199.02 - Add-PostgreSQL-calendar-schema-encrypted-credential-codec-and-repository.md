## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add the PostgreSQL schema, encrypted credential codec, and repository for calendar integrations that currently live on the retained MongoDB `users` document.

Cover calendar account identity keyed by platform identity, provider type, email, picture, enabled state, sub-calendars and their enabled state, and the calendar preferences (`calendarOptions`, primary account key, OAuth token origin).
Encrypt provider credentials (OAuth2 access/refresh/scope, Apple credentials, ICS credentials) at rest using the existing AES-GCM helper and `ENCRYPTION_KEY`, per the contract from TASK-0199.01.
Keep PostgreSQL access in server/postgres; route handlers and services must not access PostgreSQL directly.
Preserve absent-versus-explicit-false semantics and the existing email/calendar-type key behavior.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented the PostgreSQL calendar-integration persistence layer with no route wiring (deferred to TASK-0199.03) and no backfill tooling (TASK-0199.07).

Schema: server/migrations/20260910180000_calendar_integrations.sql adds calendar_accounts (platform_identity_id FK ON DELETE CASCADE, calendar_key keeping the legacy email_CALENDARTYPE key, calendar_type CHECK google/outlook/apple/ics, email, picture, nullable enabled, UNIQUE(platform_identity_id, calendar_key)), calendar_sub_calendars (calendar_account_id FK ON DELETE CASCADE, sub_calendar_id, name, nullable enabled, UNIQUE(calendar_account_id, sub_calendar_id)), calendar_account_credentials (PK/1:1 calendar_account_id; oauth access/refresh token ciphertexts, plaintext expiry and scope, apple password ciphertext, ics feed url ciphertext), and calendar_preferences (PK platform_identity_id; nullable primary_account_key, token_origin CHECK ios/android/web, JSONB calendar_options).

Codec: server/postgres/credentials.go implements authenticated AES-256-GCM with a fresh 96-bit nonce, 128-bit tag, and versioned `v1:` base64 nonce||ciphertext||tag envelope. The key is ENCRYPTION_KEY read as exactly 32 raw bytes; a missing or wrong-length key is ErrEncryptionKeyUnavailable and ValidateCredentialEncryptionKey exposes the check for startup wiring. Decryption rejects an unsupported version, truncation, and authentication failure as errors, never empty credentials.

Repository: server/postgres/calendar.go adds CalendarAccount, CalendarOAuth2Credentials, CalendarAppleCredentials, CalendarICSCredentials, CalendarSubCalendar, and CalendarPreferences types plus CreateCalendarAccount, UpsertCalendarAccount, GetCalendarAccountByKey, ListCalendarAccountsForUser, DeleteCalendarAccount, SetCalendarAccountEnabled, UpsertCalendarSubCalendar, RemoveCalendarSubCalendar, SetCalendarSubCalendarEnabled, GetCalendarPreferences, UpsertCalendarPreferences, and DeleteCalendarPreferences. Owners resolve only through platform_identities.external_user_id; a missing owner is pgx.ErrNoRows and never creates/merges/renames an account. Credentials encrypt on write and decrypt on read; empty secrets stay SQL NULL; nil enabled and nil preferences stay absent while explicit false survives, and a nil upsert never clears a stored explicit value. Only non-secret fields are stored plaintext; the postgres types are internal and are not serialized into any API response.

Tests: server/postgres/calendar_test.go adds isolated temp-table migration constraints, codec round-trip/tamper/version/wrong-key, repository credential round-trip with at-rest envelope assertions, decryption-failure surfacing (corrupted and unsupported envelopes), absent-versus-false enabled, sub-calendar add/update/remove/enable, preferences absent-versus-present, missing-owner quarantine, and list/delete cascade coverage.

Evidence: the full isolated suite `docker compose --env-file .env.test -f compose.yaml -f compose.test.yaml run --rm server-route-test go test ./... -count=1` passes; `go build ./...`, `go vet ./...`, and gofmt are clean for the changed files (the four pre-existing unformatted files were left untouched). The goose migration applied on the isolated test database (goose_db_version 20260910180000, all four calendar tables present).

DoD: no Markdown changed, so format:markdown and e2e are not applicable to this repository-only subtask; browser e2e for the calendar flows is planned in TASK-0199.07.
