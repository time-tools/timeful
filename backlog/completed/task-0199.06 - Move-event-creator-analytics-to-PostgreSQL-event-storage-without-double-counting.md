## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Move event-creator analytics off the MongoDB `events` collection and onto authoritative PostgreSQL event storage.

Replace the `creatorPosthogId` distinct and grouped aggregations in `server/db/analytics.go` with queries against PostgreSQL events.
Ensure migrated and new events are counted exactly once and no record is counted across both stores.
This task satisfies the analytics portion of TASK-0190.08 AC#3 without double counting.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
## Plan

1. Add `server/postgres/analytics.go` with repository methods:
   - `CountDistinctMonthlyActiveEventCreators(ctx, date)` -> `count(DISTINCT creator_posthog_id)` over `postgres_events` in `[date-30d, date)` with non-null/non-empty creator.
   - `CountDistinctMonthlyActiveEventCreatorsWithMoreThanXEvents(ctx, date, x)` -> grouped count with `HAVING count(*) >= x`.
   Reading only PostgreSQL means migrated and new events are each counted once, with no cross-store double counting.
2. Update `server/routes/analytics.go` to resolve `pgstore.DefaultRepository()` and call the new methods; remove `db.CountDistinct...` usage.
3. Delete `server/db/analytics.go` so the MongoDB `events` aggregation no longer exists.
4. Add `server/postgres/analytics_test.go` covering the distinct-creator window and the more-than-X threshold using the existing temp-table test helper.
5. Run backend unit tests via the isolated Compose overlay, plus the required formatting checks.

## Counting semantics

- Legacy Mongo filtered `_id` between ObjectID timestamps `[date-30d, date]` and required `creatorPosthogId` present and non-empty, with no `isDeleted` filter.
- PostgreSQL `created_at` is backfilled from the legacy creation instant, so `created_at >= date-30d AND created_at < date` reproduces the ObjectID half-open second window.
- `creator_posthog_id IS NOT NULL AND creator_posthog_id <> ''` reproduces the present-and-non-empty creator filter.
- No `is_deleted` filter, matching the legacy aggregation.

Scope confirmed: analytics-only; no schema change needed because postgres_events.creator_posthog_id already exists and the migration preserves created_at.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## Implementation

- Added `server/postgres/analytics.go` with `Repository.CountDistinctMonthlyActiveEventCreators(ctx, date)` and `Repository.CountDistinctMonthlyActiveEventCreatorsWithMoreThanXEvents(ctx, date, x)`. Both query only `postgres_events.creator_posthog_id` over the half-open window `[date-30d, date)`, require a non-null and non-empty creator, and apply `HAVING count(*) >= x` for the threshold. No `is_deleted` filter, matching the legacy aggregation.
- Updated `server/routes/analytics.go` to resolve `pgstore.DefaultRepository()` per handler and call the PostgreSQL methods with `c.Request.Context()`.
- Deleted `server/db/analytics.go`, removing the MongoDB `events` distinct and aggregate queries.
- Added `server/postgres/analytics_test.go`: window boundary inclusion/exclusion, absent and empty creator exclusion, soft-deleted counting, inclusive X threshold, and migrated-plus-new counted once.
