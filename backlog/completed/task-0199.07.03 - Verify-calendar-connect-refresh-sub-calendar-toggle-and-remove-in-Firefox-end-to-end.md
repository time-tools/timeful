## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
## Approach

The isolated test frontend runs with `VITE_ENABLE_SIGN_IN=false`, and the router guard redirects the `/auth` and `/sign-in` routes to `/home` in that mode, while the Google/Microsoft authorize URLs point at live providers. The lifecycle operations therefore run through the browser's authenticated `page.request` context (which shares the Firefox context cookie jar), matching the existing postgres e2e seeding style and the TASK-0199.07.02 route contract. The spec still renders `/settings` in Firefox after connect to prove the connection surfaces in the app.

## Deliverables

1. `e2e/helpers/mongo-inspect.ts` (new): read the retained MongoDB `users` document for an email so specs can prove the retained document is not a second authority.
2. `e2e/specs/timed-event-calendar-integration-firefox.spec.ts` (new): Firefox project spec, one behavior per test. All SQL is scoped by the owning `platform_identities.external_user_id` because the mock provider email is identical across parallel tests.
   - Connect (`page.request.post add-google-calendar-account`): assert `/settings` renders `calendar-mock@example.invalid`, assert the PostgreSQL `calendar_accounts` row plus non-null, non-plaintext encrypted `calendar_account_credentials`, and assert the retained Mongo calendar map stays empty.
   - Refresh: connect, force the credential expiry into the past with `postgresExec`, GET `/api/user/calendars` through `page.request`, then assert the expiry moved into the future and the encrypted access token changed.
   - Toggle: connect, toggle sub-calendar `work` on then off through `page.request`, assert `calendar_sub_calendars.enabled` each time and the retained Mongo map is unchanged.
   - Remove: connect, DELETE `/api/user/remove-calendar-account` through `page.request`, assert the account row plus cascaded credential and sub-calendar rows are gone and the retained Mongo map is unchanged.
