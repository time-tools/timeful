## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`server/postgres/baseline_schema_test.go` proves the consolidated baseline by asserting ten legacy columns are absent and nine platform identity columns exist. Its `hasColumn` helper resolves tables through `to_regclass`, which returns NULL for a missing table, so a negative assertion silently passed when the table itself did not exist in the transaction's temp schema. A renamed or dropped table therefore could not be distinguished from a removed column.

Tighten the helper so a missing table fails the test with a clear message, while a missing column still returns false for the negative assertions and true for the positive ones. The baseline's consolidated shape guarantee is unchanged; only the vacuous-pass failure mode is removed.
<!-- SECTION:DESCRIPTION:END -->

## Summary

Tightened `hasColumn` in `server/postgres/baseline_schema_test.go` so a missing table can no longer satisfy the negative column assertions in `TestBaselineConsolidatesAccountIdentity`. The helper now resolves table existence separately from column existence: a missing table fails the test with `table <name> does not exist`, while a missing column still returns false (negative assertions) or true when present (positive assertions). This removes the vacuous-pass failure mode where a renamed or dropped table was indistinguishable from a removed legacy column.
