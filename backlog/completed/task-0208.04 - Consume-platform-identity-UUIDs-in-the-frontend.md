## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Frontend boundary types and views still treat account and user identifiers as 24-hex ObjectID-style strings. After the backend cutover, account identity is the platform identity UUID. Update transport decoding and boundary types, remove ObjectID-based assumptions (Dashboard event sorting and signup block local _id generation currently use bson-objectid), and keep one canonical internal shape per concept. Coordinate with TASK-0177.01 so its bson-objectid removal is consistent with this change. Depends on the ADR; integrates after the backend and schema subtasks.

Constraints:
- Keep compatibility coercions and transport decoding at explicit boundaries per the frontend ADRs; do not coerce in views or composables.
- Preserve visible ordering and identity behavior unless the current behavior is proven dead; add unit coverage for any behavior change.
- Follow frontend/AGENTS.md.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Research complete. `frontend/src/types/api.ts` is regenerated and already types account/user identifiers as plain strings, so the remaining frontend 24-hex assumption is `frontend/src/utils/guestName.ts` (`OBJECT_ID_LIKE_PATTERN = /^[a-f\d]{24}$/iu`), which no longer matches the identifier form the backend rejects (`server/respondents/identity.go:67` rejects canonical UUIDs per FR-059).
2. Dashboard sorting is dead: dashboard event `_id` is the canonical short public id (`server/routes/user.go:222-223`), and `GET /user/events` returns events ordered by `created_at DESC, id DESC` (`server/postgres/dashboard.go:91`), so `ObjectID.isValid` never matches and `sortEvents` always returns 0.
3. New signup-block `_id`s are local keys: the route preserves a client `_id` only when it is a canonical UUID of a stored block and inserts a new block for every other value (`server/routes/postgres_event_routes.go:151-159`, `server/postgres/signup.go:111-176`), so a random canonical UUID would fail the row lookup; the replacement must stay non-canonical.
4. Update guest-name validation to the canonical lowercase hyphenated UUID form and rename the code/message away from ObjectID wording.
5. Remove `bson-objectid` from `Dashboard.vue` (import, comparator, all sort calls) and add Dashboard unit coverage that bucket order follows the API order.
6. Remove `bson-objectid` from `useSignUpForm.ts` and mint unique non-canonical local block keys; add unit coverage.
7. Record the reconciliation on TASK-0177.01: no import remains, so its remaining scope is the `package.json`/lockfile removal with the reachability evidence recorded here.
8. Run `npm run lint`, `npm run fmt:check`, `npm run typecheck`, `npm run build`, and `npm run test:unit` from `frontend/`; format changed Markdown.

## Final Summary

Aligned the frontend account-identity boundaries with the platform identity UUID and removed the bson-objectid call sites.

Delivered:
- `frontend/src/utils/guestName.ts` now rejects names in the canonical lowercase hyphenated UUID account-identifier form, mirroring `server/respondents.ValidateGuestName` / `models.ParseUUID` and FR-059; the validation code is renamed to `accountIdLike`, and the retired 24-hex form is accepted as an ordinary name. Updated `guestName.test.ts` and `EditingAvailabilityAs.test.ts`.
- `Dashboard.vue` no longer imports `bson-objectid`: the ObjectID-timestamp comparator and all bucket sorts are removed because dashboard events expose the canonical short public id as `_id` and `GET /user/events` orders by `created_at DESC, id DESC`, so every comparison already returned 0.
- `useSignUpForm.ts` no longer imports `bson-objectid`: new blocks get a unique `local-signup-block-<n>` key from `mintLocalSignUpBlockId()`, which the route maps to a new stored block; a canonical random UUID would instead be forwarded to `ReplaceSignupBlocks` and fail with no matching row.
