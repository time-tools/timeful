## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Move OTP challenge storage from MongoDB `otpCodes` to PostgreSQL while preserving the existing send and verify semantics in `server/routes/auth.go`.

Preserve the ten-minute expiry, the five-attempt lockout, delete-on-success, and delete-existing-before-insert behavior.
Replace the MongoDB TTL index with a PostgreSQL cleanup strategy.
Keep successful authentication resolving an authoritative PostgreSQL account.
Remove the `OtpCodesCollection` runtime usage and TTL index creation.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Added `server/migrations/20260910190000_otp_challenges.sql`: `otp_challenges` (fresh `id`, unique normalized `email`, `code_hash`, `expires_at`, `attempts`) plus an `expires_at` index for the explicit sweep, no backfill needed because challenges are ephemeral.

Added `server/postgres/otp.go`: `CreateOtpChallenge` upserts and resets attempts (replacing any existing challenge); `VerifyOtpChallenge` runs a single row-locked `UPDATE ... attempts = attempts + 1 ... WHERE email AND expires_at > clock_timestamp() ... RETURNING`, deletes and returns `ErrOtpTooManyAttempts` past the fifth attempt, and deletes on a matching code; `DeleteExpiredOtpChallenges` sweeps expired rows; `DeleteOtpChallenge` supports cleanup. Codes are stored as `base64(salt):base64(HMAC-SHA256(salt, code))` with a per-challenge 16-byte salt and constant-time comparison, never plaintext.

Updated `server/routes/auth.go`: `sendOtp` sweeps expired challenges then upserts a fresh 10-minute challenge; `verifyOtp` maps `ErrOtpExpired`/`ErrOtpInvalidCode`/`ErrOtpTooManyAttempts` to the existing 400/400/429 responses and still resolves the authoritative PostgreSQL account. Removed the MongoDB `mongo` import.

Removed `OtpCodesCollection` and the MongoDB TTL index from `server/db/init.go` and deleted the unused `server/models/otp.go`.

Tests: new `server/postgres/otp_test.go` covers hashing/replace, success delete, expiry, wrong-code attempt increments, lockout delete, and the expiry sweep. Updated the route `insertOtpCode` helper in `server/routes/accounts_test.go` to seed PostgreSQL. Updated the e2e seeders (`e2e/helpers/postgres-inspect.ts` gains `postgresExec` and `seedOtpChallenge`; `e2e/helpers/account-auth.ts` and the access-transfer spec use it) because the app no longer reads `otpCodes`.

Verification: `go build ./...` and `go vet ./...` clean; `docker compose ... run --rm server-route-test` passes the full Go suite including `timeful/server/postgres` and `timeful/server/routes`; focused e2e `account-deletion.spec.ts -g "re-signing in after deletion"` passes on chromium-desktop; e2e `typecheck`, `lint`, and `fmt:check` are clean. No repository Markdown changed, so `npm run format:markdown` is not applicable.
