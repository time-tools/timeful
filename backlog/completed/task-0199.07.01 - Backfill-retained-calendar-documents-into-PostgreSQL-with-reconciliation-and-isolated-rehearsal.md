## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Provide the resumable backfill and reconciliation for moving existing retained calendar integration data from MongoDB into PostgreSQL.

Add a dated one-off command under server/scripts that reads retained MongoDB users calendar documents and preferences, resolves owners through platform_identities.external_user_id, writes PostgreSQL calendar records with encrypted credentials, records progress in the migration ledger, and never modifies MongoDB source data. Migrate one account per unit covering its connections, credentials, sub-calendars, and preferences; re-encrypt any legacy AES-CFB Apple password with the AES-256-GCM envelope. Quarantine a retained document whose owner has no platform identity as missing-owner-account.

Add reconciliation for per-kind counts, enabled flags, sub-calendars, preferences, and credential round-trip. Cover interruption and rerun: replay skips completed units, and an interrupted run resumes from the first incomplete unit.

Use the isolated Compose test stack for the rehearsal. Cover representative Google, Outlook, Apple, and ICS accounts, preferences, a two-connection account with a legacy key suffix, and a retained account with no PostgreSQL account row yet.
<!-- SECTION:DESCRIPTION:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Added the resumable MongoDB-to-PostgreSQL backfill for retained calendar integrations, with reconciliation and an isolated rehearsal.

What changed:
- server/postgres/repository.go: added NewRepositoryFromTx so a caller that owns a transaction can compose repository writes with its own SQL atomically.
- server/scripts/20260911_mongo_calendars_to_postgres/main.go: dated one-off CLI (--apply, --batch-size, --limit, --batch-label, connection flags), user pagination, migration ledger and quarantine helpers, and reconciliation entry point. Read-only by default; fails the run on a reconciliation mismatch.
- server/scripts/20260911_mongo_calendars_to_postgres/calendars.go: one unit per retained owner account covering every connection, credential, sub-calendar, and preference. Resolves owners through platform_identities.external_user_id plus an accounts row, quarantines missing owners as missing-owner-account without creating an account, decrypts the legacy AES-CFB Apple password, preserves legacy map keys including mixed case, and writes all target rows plus the ledger row in one transaction.
- server/scripts/20260911_mongo_calendars_to_postgres/reconcile.go: unit and per-kind counts joined through the ledger, a v1: GCM-envelope check for every stored credential, quarantine breakdown, and mismatch reporting.
- server/scripts/20260911_mongo_calendars_to_postgres/support.go: ledger/quarantine kinds, reason code, page filter, and a fail-closed legacy CFB decrypt.
- server/scripts/20260911_mongo_calendars_to_postgres/main_test.go: pure unit tests for connection mapping (enabled nil vs false, OAuth expiry, sub-calendar state), Apple CFB to plaintext conversion, preferences absent vs present, and report formatting.
- server/scripts/20260911_mongo_calendars_to_postgres/main_integration_test.go: isolated rehearsal with Google (tokens, scope, expiry, enabled/disabled/absent sub-calendars), Outlook (absent enabled), Apple (CFB password), ICS (feed URL and label identity), a two-connection mixed-case legacy key account, a preferences-only account, and a missing-owner quarantine. Asserts target counts, decrypted credential round-trip, the raw v1: envelope, source-document immutability, quarantine breakdown, clean reconciliation, idempotent replay, and --limit resume.
- server/docs/postgres-core-migration-runbook.md: new Retained Calendar Backfill section documenting tooling, flags, unit/ledger kind, owner resolution, credential re-encryption, reconciliation checks, and the rehearsal command; corrected the statement that calendar collections are never copied.
