## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Why

Two independent problems, both in `.agents/skills/gala-from-go/`.

**The skill is not project-independent.** It is staged for upstream, per `gala-rewrite/SKILL.md`, but `references/gaps.md` links into this repository's probe corpus and into the vendored runtime. Two links break portability, and both carry a fact that belongs in the sentence rather than in the link.

**The skill demands more evidence than it teaches.** Its verification section states that a transpile settles neither a shape claim nor a runtime-observable difference, and that only the emitted text settles what was generated. But `constructs.md`'s `Check` column tells a reader to pin a row by transpiling a minimal form, and its `Pinning A Row` section offers only scratch commands. The skill is internally inconsistent about the standard of evidence it holds itself to, and the method that produced the defects already recorded in `gaps.md` is undocumented.

The method exists in this repository. It is written down in `docs/gala-translation.md`'s probe-corpus section, which is the least portable place it could be in, because it documents a capability rather than a project fact.

## Outcome

The claim-to-pin method lives in the skill, and the skill is free of repository paths.

This subtask is independent of the rest of TASK-0339 and may land first.

## Scope

A new `references/probes.md` owns the method, and the existing sections are reconciled rather than duplicated. The discipline to preserve: this repository's problem is four copies of one idea, so a new reference must own a question no existing file owns.

- **What `probes.md` owns:** how to construct an assertable pin for a claim, given the claim. The four pin kinds and the one thing each may prove. The marker rules. The control experiment for a mixed-package effect. The direction rules for gating prose against pins, in both directions, and the rule that a gap claim needs a failing pin of an admissible kind.
- **What it does not own:** the taxonomy of claims, which `SKILL.md`'s shape-claim section already states, and the substitutions, which `constructs.md` owns. Restating either is a fourth copy and defeats the task.
- **Version-pair deltas are explicitly out of scope.** A pin whose meaning is a change between two named releases is a project record, not a method. The skill's existing rule is that rows are version-agnostic and name a check rather than a release, and this subtask does not relax it.

Then reconcile `constructs.md` so its `Check` column and its `Pinning A Row` section no longer imply a transpile proves more than the skill says it proves, and remove the two repository-relative links from `gaps.md` by inlining their facts.

## A related finding, recorded rather than fixed here

`audit.sh` check 7 verifies that every Markdown table row in five enumerated documents has the same cell count as its own header, and the five documents are a hard-coded list. A new reference file is therefore silently outside the audit until somebody edits a list by hand. That is the same class of defect this task exists to remove, in a different artifact. Decide here whether the new file is added to the enumeration or the enumeration is replaced by a discovery rule, and record which; do not leave a new table outside the audit.

The check is a real gate on this subtask rather than a formality, because the existing `constructs.md` already contains a match arm written as an escaped pipe that the check specifically has to not misread, so the new file's tables are in scope the moment it is added.

## Constraints

- The skill's existing rules are not relaxed: rows stay version-agnostic, name a diagnostic code or a check rather than a release, and a claim is settled by reading the emitted Go or running the program rather than by a clean transpile.
- The repository's probe corpus stays where it is and is not modified. It is a valid evidence store; it is not portable documentation.
- `gala` 0.84.1 and the go1.26 series stay the pinned toolchains, and the vendored runtime under `server/third_party/gala/` is unchanged, so the two inlined facts are transcribed rather than re-derived.
- The gap-classification scheme and the report template in `gaps.md` are not restated in the new file.
- Root Markdown follows the sentence-per-line and table-row rules in `docs/AGENTS.md`.

## Evidence required

Record which claim in the skill's own text is no longer provable by the check it names, since that is the specific defect being repaired.
Record the decision taken on the audit's document enumeration.
