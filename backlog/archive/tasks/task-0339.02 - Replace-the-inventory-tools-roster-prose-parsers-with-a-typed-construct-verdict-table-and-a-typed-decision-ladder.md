## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Why

`inventory/roster.go` turns prose into control flow.

A construct verdict today is a Markdown cell, and the file-level verdict the preflight prints is derived from it by substring-matching four hand-written phrases, with a hard-coded negation for one specific phrasing. The decision ladder is recovered the same way: each rung label is matched for the words `split`, `keep handwritten`, and `rewrite`, so rung 2 is the split rung because its label happens to contain the word the split test looks for before the word the rewrite test looks for, and `rewrite` is only recognised on rung 1.

`roster_test.go` then pins the English. A test that asserts this exact sentence classifies as a split asserts the coincidence, not the intent, so it locks the wording in place without protecting the behaviour.

The exposure is specific. The preflight is advisory and its documented contract is that a construct family the roster does not classify is blocking, because a verdict line that reads like a decision is not one. That safety property currently rests on a phrase matching. An edit that rewords a verdict cell to `leave the file Go` reclassifies the family as a full rewrite, prints a rewrite verdict, and exits `0`.

## Outcome

The tool holds construct verdicts as typed data and reads them directly. No English decides a strategy or a rung, and a family the tool cannot classify is caught by a failing test rather than by a runtime branch that prints a warning.

This subtask does not change the roster page. It changes where the page's data comes from, and it removes the two prose parsers so that the next subtask has a single typed input to emit from.

## Scope

- **Typed data.** Gap class and file strategy become distinct types with a closed set of values. The decision ladder becomes a typed ordered sequence whose rungs carry a strategy, rather than labels recovered by pattern matching.
- **One field for the nuance, never parsed.** A verdict cell today packs a gap class, a file strategy, the rewrite spelling, and a condition, and the strategy is the only part a machine needs. The rest is explanation. Carry the explanation in a field that is displayed and never read back, so the conditional verdicts keep their nuance without the nuance being able to change a classification.
- **Completeness becomes a test.** Every family the detector can emit has exactly one row. The current runtime behaviour, which prints that a family is not classified and carries a zero rung, becomes a failing test. That is the single most valuable change here, because it converts the tool's most important safety property from a runtime message into a build-time failure.
- **Delete the parsers.** The two readers that parse the roster section and the census table out of the page are removed, together with the tests that pin their phrase matching. The preflight prints the decision ladder from the typed ladder, in words, because the output is read by a person and a person needs the wording.
- **Preserve the exit-code contract.** `0` for every verdict including the one that says stop. `2`, `3`, and `4` continue to mean the tool could not answer rather than the file being blocked. Exit `3` changes meaning from a restructured page to an incomplete table, and every place the status is documented is updated in the same change rather than left to drift.

## Constraints

- The page's content is unchanged by this subtask. The preflight must print the same verdicts for the same files as it does today, which is how the typed table is validated against the prose it replaces.
- No verdict is silently reclassified in the transcription. Where a cell's prose is ambiguous, that ambiguity is recorded rather than resolved by picking a reading.
- The verdict cells' explanatory content is preserved. Losing it is how a future agent re-derives a wrong substitution.
- `audit.sh` still runs and is still read-only. Its roster checks are expected to fail or go redundant once the page stops being the source; that rework is the next subtask and is explicitly not done here.
- `gala` 0.84.1 and the go1.26 series stay the pinned toolchains, and the vendored runtime is not modified.
- The tool stays a single nested module at its current path, and the corpus layout is unchanged.

## Evidence required

Record a per-family comparison of the strategy the prose produced and the strategy the typed table produces, and confirm they are identical. Any divergence is a transcription error to fix, not a verdict to correct.
Record the exit statuses observed for an unparseable file, an unknown family, and a clean run, before and after.
