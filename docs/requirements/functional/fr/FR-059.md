# FR-059: Validate And Normalize Event Response Names

Before creating or updating an [Event Response](../../../terminology/glossary.md#event-response), the system shall remove control and Unicode-format characters, trim whitespace, and normalize its name to [Unicode Normalization Form C (NFC)](../../../terminology/glossary.md#unicode-normalization-form-c-nfc).

## Acceptance Criteria

- The normalized [Event Response](../../../terminology/glossary.md#event-response) name must be non-empty and no more than 100 code points.
- The system shall reject names that look like the account identifier in its lowercase hyphenated UUID form.
- [Event Response names](../../../terminology/glossary.md#event-response) compare case-sensitively after normalization.
- An [Event Guest](../../../terminology/glossary.md#event-guest) may own multiple [Event Responses](../../../terminology/glossary.md#event-response) for the same event.
- [Event Response](../../../terminology/glossary.md#event-response) display names shall be unique within an event across all guests: two different guests shall not use the same display name after normalization.
- When a signed-in guest's profile-derived default name ([FR-080](FR-080.md)) is already used within the event, the system shall reject the creation or update until the guest chooses a distinct display name.
