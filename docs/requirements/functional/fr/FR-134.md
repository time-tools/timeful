# FR-134: Show The Response Selection Control Beside The Availability Status

Outside [Blind Availability Mode](../../../terminology/glossary.md#blind-availability-mode), while the system lists [Event Responses](../../../terminology/glossary.md#event-response) for selection, each listed row shall show its response checkbox beside the row's [Availability Status](../../../terminology/glossary.md#availability-status) for the [Slot](../../../terminology/glossary.md#slot) in context, or beside the avatar when no **Slot** is in context, instead of replacing it.

On a phone viewport, every row shall show its response checkbox without a hover.

On a desktop viewport, an unselected row shall show its response checkbox only while hovered, and a selected row shall keep its response checkbox visible.

The unchecked response checkbox shall use the neutral outline, and its hovered and selected states shall use the primary action color.

Showing, hiding, or toggling a response checkbox shall not move the [Event Response](../../../terminology/glossary.md#event-response) name or change the row height.

## Acceptance Criteria

- A selected row shows both its [Availability Status](../../../terminology/glossary.md#availability-status) and a checked response checkbox.
- The response checkbox appears immediately to the right of the availability status indicator or avatar.
- On a phone viewport, an unselected row that is not hovered still shows its response checkbox.
- On a desktop viewport, revealing the response checkbox on hover moves neither the [Event Response](../../../terminology/glossary.md#event-response) name nor any other row content.
- Toggling the selection leaves the row name at the same horizontal position.
