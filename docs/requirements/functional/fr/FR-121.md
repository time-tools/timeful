# FR-121: Serve Records From A Single Authoritative Store

The system shall serve every record kind's reads and writes from exactly one authoritative store.
The record kinds are accounts and profiles, [Timed Events](../../../terminology/glossary.md#timed-event), [Dates-Only Events](../../../terminology/glossary.md#dates-only-event), day-of-week events, availability groups, signup forms, [Event Responses](../../../terminology/glossary.md#event-response), attendees, folders, folder membership, [Calendar Connections](../../../terminology/glossary.md#calendar-connection), provider credentials, sub-calendars, calendar preferences, OTP challenges, and historical daily user logs.

PostgreSQL is the sole authoritative store for every record kind, and the system shall not read or write any record kind from a second store.
Each account reference shall resolve to exactly one account identity.
Friend requests are not stored and have no authoritative store.

Automated tests over representative records show one authoritative value per record and no duplicate account identity.
