# FR-062: Restore Event Guest Access After Event Sign-In

When an [Anonymous Event Visitor](../../../terminology/glossary.md#anonymous-event-visitor) with an active [Granted Event Visitor Control Credential](../../../terminology/glossary.md#granted-event-visitor-control-credential-granted-evcc) signs in, the system shall obtain explicit confirmation before associating the response-owning source [Event Visitor Identity](../../../terminology/glossary.md#event-visitor-identity) with the visitor's [Platform Visitor Identity](../../../terminology/glossary.md#platform-visitor-identity) for durable recovery.
It shall not substitute the current browser's [Event Visitor Identity](../../../terminology/glossary.md#event-visitor-identity) as the response owner.

The sign-in association of the current browser's [Event Visitor Identity](../../../terminology/glossary.md#event-visitor-identity) with the visitor's [Platform Visitor Identity](../../../terminology/glossary.md#platform-visitor-identity) still applies as [FR-079](FR-079.md) defines; the explicit confirmation governs only the response-owning source **Event Visitor Identity**.
The [Granted Event Visitor Control Credential (Granted EVCC)](../../../terminology/glossary.md#granted-event-visitor-control-credential-granted-evcc) shall remain active after the association until the source revokes it or the target browser's data is cleared.

On another browser, a [Platform Visitor Identity](../../../terminology/glossary.md#platform-visitor-identity) shall be able to edit every [Protected Event Response](../../../terminology/glossary.md#protected-event-response) created by an associated [Event Visitor Identity](../../../terminology/glossary.md#event-visitor-identity).
For an event not owned by that **Platform Visitor Identity**, association of a new **Event Visitor Identity** alone shall not authorize a [Protected Event Response](../../../terminology/glossary.md#protected-event-response) created by a different **Event Visitor Identity**.
