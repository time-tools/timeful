# QR-017: Keep Serving Requests When Observability Ingestion Fails

## Source

OpenObserve or the network path to it.

## Stimulus

OpenObserve is unavailable or slow while the server handles requests.

## Environment

Staging or production; representative request load; [Observability Data](../../../terminology/glossary.md#observability-data) export is enabled.

## Artifact

The server's request handling and its local [Diagnostic Output](../../../terminology/glossary.md#diagnostic-output).

## Response

The server shall continue to serve requests without [Observability Data](../../../terminology/glossary.md#observability-data) export blocking or failing the request path, and shall retain local [Diagnostic Output](../../../terminology/glossary.md#diagnostic-output) while OpenObserve is unavailable.

## Response Measure

An operational exercise stops or stalls OpenObserve and drives representative requests.
The request success rate is unchanged, request latency stays within the bounds of [QR-006](QR-006.md) and [QR-007](QR-007.md), and local [Diagnostic Output](../../../terminology/glossary.md#diagnostic-output) is still available after the exercise.
