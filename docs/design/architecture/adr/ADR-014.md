# ADR-014: Quarantine Legacy Guest Credentials And Ambiguous Ownership

> **Inactive.**
> Deprecated on 2026-09-11 after the data move completed.
> Retained for decision history and must not be followed as a current decision.

No quarantine tooling remains in the repository.

## Context

Legacy MongoDB responses may carry `guestEditToken` values and ambiguous ownership, and legacy accounts may be referenced by events whose owner account no longer exists.
The [PostgreSQL Event API Contract](../../../../server/docs/postgres-event-api-contract.md) defines event authority through Event Visitor Control Credentials, Granted Event Visitor Control Credentials, and Event Owner Edit Tokens, and no existing base credential is promoted to owner authority.
The migration must therefore decide what PostgreSQL does with legacy credentials and unattributable records without inferring authority.

## Considered Options

- Import legacy guest edit tokens into PostgreSQL as base [Event Visitor Control Credentials](../../../terminology/glossary.md#event-visitor-control-credential-evcc).
- Keep serving legacy credentials for migrated records through a compatibility path.
- Quarantine legacy credentials and ambiguous ownership, import no authority, and report the decisions.

## Decision Outcome

Chosen option: "Quarantine legacy credentials and ambiguous ownership, import no authority, and report the decisions", because it preserves the existing authorization model and refuses to infer authority the source does not establish.
Migrated guest responses are owned by a fresh [Event Visitor Identity](../../../terminology/glossary.md#event-visitor-identity) but receive no base EVCC and no [Event Owner Edit Token](../../../terminology/glossary.md#event-owner-edit-token).
Legacy `guestEditToken` values are recorded only in the migration ledger with their legacy response identity, event identity, quarantine reason, and batch.
Ownership already associated with a [Platform Visitor Identity](../../../terminology/glossary.md#platform-visitor-identity) is preserved, and no legacy credential is promoted to owner authority.
Ambiguous records are quarantined with distinct reason codes and never repaired by inference, and a guest whose legacy token is quarantined regains PostgreSQL authority only by establishing new authority, such as a new response or association through [Event Sign-In](../../../terminology/glossary.md#event-sign-in).

## Consequences

- Good, because legacy credentials cannot silently broaden into event-scoped or owner authority.
- Good, because unattributable records are reported and auditable rather than guessed.
- Bad, because guests with only a legacy credential lose the ability to edit their migrated response until they establish new authority.
- Bad, because quarantined records require operational follow-up at cutover.
