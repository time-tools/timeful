# Go to GALA translation roster

This page answers "given this Go construct in `server/`, what is the GALA rule, and can I use it?" for the constructs this project actually uses.
It is the durable reference built by TASK-0322 from the spike record in [`../server/GALA.md`](../server/GALA.md), the runtime vendored under `server/third_party/gala/`, and the upstream sources listed at the end.
The generation and verification procedure for the committed twins lives in [`../server/README.md`](../server/README.md).
The vendored runtime and the probe harness are pinned to GALA 0.84.1.
PR [#529](https://github.com/martianoff/gala/pull/529) landed in that release, so [Compiler history](#compiler-history) is the record of what changed rather than a forward-looking status column.

## Sources and scope

- The roster is derived from an AST inventory of every `.go` file in the server Go module, skipping nested modules such as `third_party/` and the probe corpus; the method and counts are in [Inventory](#inventory), and `inventory/main.go -check` re-derives them.
- Every construct family in that inventory has an entry in [Construct roster](#construct-roster) with a minimal Go repro, the GALA rewrite or the documented blocker, both version statuses, an upstream reference, at least one `file:line` use, a gap class, and a verdict.
- The scripted corpus in `server/scripts/20260923_gala_translation_probes/` keeps the blocked, contested, decision-rule, and emitted-shape verdicts honest; see [Probe corpus](#probe-corpus), and `audit.sh` checks the roster, the corpus, and [`../server/GALA.md`](../server/GALA.md) against each other.
- Upstream references: [`GALA.MD`](https://github.com/martianoff/gala/blob/master/docs/GALA.MD), [`GALA_BEST_PRACTICES.MD`](https://github.com/martianoff/gala/blob/master/docs/GALA_BEST_PRACTICES.MD), [`website/llms.txt`](https://github.com/martianoff/gala/blob/master/website/llms.txt), the [`gala-lint` skill](https://github.com/martianoff/gala/blob/master/ide/claude-code/skills/gala-lint/SKILL.md), and the `gala explain GALA-Exxxx` pages.
- The stale `website/features/go-interop.md` is deliberately not a source: it claims bare `len`/`make`/`cap` work, which `GALA.MD` §11 and the probes contradict.

## Decision ladder

Choose the first rung that fits.

1. **Rewrite runtime-free.**
   Use this for a leaf file whose exported Go API must stay exactly Go-shaped.
   Bind raw Go values with `var`, import Go packages directly, avoid `val`/`Option`/`Try`/collections, and use `.ByteSize()`/`.Size()` plus the `go_interop` helpers in place of `len`, `make`, `append`, and `[]byte`.
   The committed `eventid`, `observability/redact`, `logger`, `request_utils`, `services`, `guest_response_ownership`, `providerconfig`, and the generated half of `utils` twins show the style.
2. **Rewrite runtime-enabled, or split with a handwritten sibling.**
   Use runtime-enabled output when the file benefits from `val`, `Option`/`Try`/`Either`, sealed types, or immutable collections, and its Go callers tolerate the emitted shapes.
   Split when only some members are inexpressible (multi-value returns, `defer`-heavy cleanup, tags): keep those members in a handwritten `.go` sibling and transpile the rest, as `appenv/appenv_port.go`, `utils/array_utils_extra.go`, and `slackbot/commands/utils.go` do.
3. **Keep handwritten.**
   Use this for any file whose shape is blocked (struct tags, `interface{}`, fixed-size arrays, named scalar receivers, anonymous structs, embedded fields, type assertions, slice expressions, map literals, inline function literals in composite literals, `const`, `switch`, `defer`-dependent control flow) or whose Go callers cannot tolerate the GALA shapes.
   `models/{datetime,uuid,set,location,event}.go`, `errs/errors.go`, `middleware/auth.go`, `postgres/`, and `main.go` stay here today.

Two shape rules apply on every rung:

- An exported package-level `val` emits `var X = std.NewImmutable(...)`, so Go callers must call `.Get()`; keep `var` for anything that crosses into Go.
- A GALA struct declaration is not a drop-in twin: the transpiler synthesizes exported `Copy`, `Equal`, and `Unapply` members on it, adds an `Instance` interface and an `Is<Type>` method when the struct is generic, and wraps fields in `std.Immutable[T]` unless they are declared `var`.

## Gap classification

The `Gap class` column records what a construct costs when it is not a direct form; it is separate from the verdict's file strategy.

- `—`: the construct is a direct form, and no substitution is involved.
- `analog`: a GALA-native construct expresses the same behavior, such as `match`, `Try`, `use`, or `.ByteSize()`.
- `workaround`: only an interop helper or a plain-Go spelling preserves the behavior, such as a `go_interop` helper, a preceding `var`, or `any`.
- `language gap`: GALA has no syntax or semantics for the construct, so nothing in the language expresses it.
- `boundary gap`: GALA can express the behavior, but not as a Go-shaped drop-in, so a Go API or a wire format would change.

A genuine gap is a row classified `language gap` or `boundary gap`.
Every genuine gap has a `GAP-n` entry in [Genuine gaps](#genuine-gaps), and each entry names at least one failing, non-contested probe; a `contested_*` probe can never back a gap claim.
Rows classified `analog` or `workaround` have a substitute rather than a gap, and they are listed in [Replaced by analog or workaround](#replaced-by-analog-or-workaround).

## Compiler history

The harness and the vendored runtime are pinned to GALA 0.84.1, and every status in [Construct roster](#construct-roster) describes that release.
This section is the changelog for reaching it, so the pre-0.84.1 record survives without costing a column in the roster.

PR [#529](https://github.com/martianoff/gala/pull/529) landed in 0.84.1 and fixed seven behaviors that 0.81.0 got wrong, so each of them flipped as this page predicted it would:

- Multi-value `:=` receive, `a, b := f()`, used to abort with an internal `GALA-E0017` transpiler panic and now transpiles; it is a val-style binding, so it wraps each result and emits `.Get()` at every read, while `var a, b = f()` emits a plain Go binding; `emit_multi_value_define_wraps` and `emit_multi_value_var_plain` pin the two halves of that difference, because a wrong claim about it once survived here, in [Decision ladder](#decision-ladder), and in the corpus.
- Alias conversion for a scalar, `type Millis int64` then `Millis(v)`, used to emit `Millis{}`, drop the argument, and fail `go build`; it now emits the Go conversion.
- Alias conversion for a struct alias, `type Coord Point` then `Coord(1, 2)`, used to emit `Coord{}` and silently return zero values; it now follows the alias chain to the original field list.
- A trailing `if (c) { a } else { b }` used as a block value used to emit bare expression statements and fail `go build` with `missing return`; each branch is now promoted to a return.
- `if init; cond` used to bind `std.Immutable[error]` and fail `go build` with a type mismatch; it is now rejected at transpile time as `GALA-E0047` with a `Try` hint.
- `for ; cond; post` with the init omitted used to assign the statements by list position, running the post statement once before the loop; the slot is now decided from the `;` separators.
- An alias to an instantiated generic struct used to emit `Alias{}` and silently return zero values instead of passing the arguments; the alias chain is now resolved and the arguments passed.

0.84.1 also added a diagnostic this page did not previously record.
A method on a type alias is now rejected at transpile time as `GALA-E0048`, where 0.81.0 accepted the declaration and emitted Go that failed to build; see the `methods-on-defined-non-struct` and `defined-non-struct-types` rows in [Construct roster](#construct-roster).

Two of the seven fixes change the answer for construct families the server uses, so the decision ladder above now reaches further.
`multi-value-define` is a direct form, which is the top ask in [Genuine gaps](#genuine-gaps), and `defined-non-struct-types` keeps only its method half, which is `GAP-4`.

Still blocked in 0.84.1, exactly as they were in 0.81.0: `type X Y` stays a Go alias, so methods on named scalars stay illegal, and `defer`, `switch`, struct tags, `interface{}`, fixed-size arrays, type assertions, slice expressions, and map literals are all unchanged.
The probe corpus pins each of those.

## Inventory

The counts below come from `inventory/main.go` in the probe corpus, a pre-order `go/parser` and `go/ast` pass over the server Go module with nested modules skipped; run `go run ./inventory -check` from the corpus directory to re-derive the counts, the class totals, and the representatives, or `go run ./inventory` to print them.
Each parsed file is classified as handwritten or generated (a `DO NOT EDIT` marker in its comments) and as test or non-test.
Generated files split further into GALA twins (15) and the swag-generated `docs/docs.go` (1).
Occurrences are counted per construct instance, and the representative is the first hit in a handwritten non-test file, falling back to the first hit in any class.
`go run ./inventory -preflight path/to/file.go` applies the same detection to one Go file: every construct family it contains with an occurrence count and a `file:line` representative, that family's `Gap class` and `Verdict` copied from the [Construct roster](#construct-roster), and the decision-ladder rung the verdict reaches.
The mode prints the decision ladder in the roster's own words, then one file-level verdict, which is the highest rung any family in the file needs, so a file that rewrites whole is distinguishable from one that needs a handwritten sibling and from one that stays handwritten.
The verdict is advisory and gates nothing, so a file the roster keeps handwritten still exits 0; the mode exits 2 for a file it cannot read or parse, 3 for a missing or restructured roster, and 4 for a file with no recognized construct family.
It finds the construct roster by section and by table header, so a verdict moved to another column, or a same-shaped table elsewhere on this page such as [Replaced by analog or workaround](#replaced-by-analog-or-workaround), cannot be mis-mapped; a family it detects that this page does not classify is printed as `not classified in the roster`, which is a row to add here rather than a verdict to guess.
A construct family recorded at zero occurrences has no roster entry; those families are `cap-calls`, `array-literals`, `dot-imports`, `go-embed-directives`, `for-loops-with-omitted-init`, `goto`, `fallthrough`, `labeled-statements`, and `iota`.
Five roster families are properties of a call site rather than a syntactic shape the scanner detects, so they carry a location or an explicit absence instead of a count: `binding-method-receivers`, `gala-type-go-sibling-method`, `bare-type-name-resolution`, `expression-body-no-return`, and `var-tuple-destructuring`.
`new-calls` is the one family whose occurrences are all in generated files and it is listed rather than dropped: the transpiler emits `*new(T)` into the `Unapply` it synthesizes for every GALA struct, so a struct twin makes the count non-zero without the source containing a single `new` call.
The inventory covers 168 Go files: 79 handwritten non-test, 73 handwritten test, 15 GALA-generated, and 1 swag-generated.

## Workarounds and contested verdicts

These are the entries the probe corpus pins with scripted expectations.
Every conditional verdict above is a decision rule with a probe per branch.

### Multi-value bindings

The mechanical rewrite is `x, y := f()` to `var x, y = f()`; plain reassignment and blank receives already work.
The rewrite is a shape choice rather than a repair, because `:=` transpiles on its own: it binds each result through an immutable wrapper and the transpiler inserts `.Get()` at every read, while `var` emits a plain Go binding.
Take `var` for anything a Go caller or a sibling `.go` file can see, and `:=` only for a binding that stays inside the transpiled file.
`delta_multi_value_define` pins that the `:=` receive transpiles, builds, and produces the right value, and `pass_multi_value_bindings` pins the `var`, reassignment, and blank-receive forms.
Neither of those probes can see the emitted shape, because a wrapper the program never observes is invisible to a probe that only asserts the program's output.
`emit_multi_value_define_wraps` and `emit_multi_value_var_plain` are the same program in the two spellings, and they are what makes the difference checkable: the first asserts the wrapper constructor and the two `.Get()` reads are emitted, the second asserts all three are absent.
The absence half carries the claim, because a transpiler that started wrapping both spellings would pass every output probe in the corpus and fail only these two.

### Lambda parameter inference

`GALA-E0033` names three contexts that permit an unannotated lambda parameter: a typed `val`, a function argument, and a return.
All three hold, so the hint is accurate.
`pass_lambda_return_inference` pins the return position, which is the case a `direct` construct row had recorded as refused: a block-bodied lambda in return position emits `func(x int) int` and runs.
Only two shapes are refused, and both refusals are correct: a bare untyped `val` initializer, where there is no type to draw from, and a generic type parameter such as `func F[T any]() T = (x) => x`, where the concrete type is not yet known.

### Method-call receivers on a binding

A method call on a `:=` or `val` binding is lowered into a read of the binding, so the emitted Go unwraps the receiver and calls the method on the copy.
`blocked_receiver_unwrap_samepkg` and `blocked_receiver_unwrap_val` pin both spellings, and `emit_var_receiver_no_wrapper` pins the `var` spelling of the same program, which emits neither the wrapper nor the unwrap.
`var` is therefore the only safe spelling of the three rather than a style preference.
The failure needs a pointer-receiver method to be visible, because a value-receiver method on an unwrapped copy builds and runs, so one source is either a build failure or a quiet copy depending on the method set.
Filed as #614.

### A method declared in a handwritten sibling

The receiver's method set is read from the file being transpiled only.
A method called on a type the transpiler does not know passes through and Go resolves it; a type declared in the `.gala` file is judged against a method set that excludes a handwritten sibling's, so the call is refused with `GALA-E0044` and a hint that says the type declares no methods.
`blocked_e0044_go_sibling_method` pins it, and the control is one file extension: the same three declarations with the sibling transpiled as `.gala` build.
This is the constraint that rules out a whole-file rewrite for 12 of the 14 rung-2 `postgres` candidates, because `Repository` is declared in a rung-3 sibling with 106 methods across twelve files.
Filed as #615.

### Forms that lose a result type

Two unrelated shapes, each with a one-word rewrite.
`func F() = <expr>` never infers a result type, so the emitted Go function is void and its body returns a value; writing the type out is the fix (`blocked_expression_body_no_return`, `pass_expression_body_typed`, #617).
`var (a, b) = f()` reaches the transformer with a nil `IdentifierListContext` and panics with `GALA-E0017`, while the `val` spelling of the same destructuring transpiles, builds and runs (`blocked_var_tuple_pattern`, `pass_var_tuple_val_form`, #620).
A multi-value binding still takes no type annotation, because the grammar's single `(type)?` slot sits after the whole name list, which is a grammar shape rather than a missing construct.

### Switch-shaped matches

Rewrite a `switch` to `match` when every case is a literal pattern, with `case _` as the default.
A `case` that names a constant binds a new name instead of comparing, so it rewrites manually to an `if`/`else` comparison chain, the style the committed `appenv` twin uses; `fallthrough` stays handwritten.
`pass_match_switch_shape` pins the literal form, and `blocked_switch` pins the parse error.

### `.Size()` versus `.ByteSize()` and field access

`.ByteSize()` preserves Go `len` byte semantics, so a direct rewrite of a byte-counting `len` uses it; `.Size()` is only for an intended character count, and GALA collections use `.Size()` for the element count.
Both lower to runtime-free Go: `.Size()` emits `utf8.RuneCountInString`, and `.ByteSize()` emits Go `len`.
The contested part is field access: `.Size()` lowers on a field whose type the transpiler knows from a GALA declaration (`pass_size_field_gala_struct`), but with the struct declared in a handwritten Go sibling it emits `c.Usage.Size()` and `go build` fails (`contested_size_field_go_sibling`), which is why the twins compare strings with `!= ""`.
PR #529 notes this did not reproduce standalone, and the probe agrees; it is specific to the mixed `.gala` plus handwritten `.go` package.
Two more shapes belong here, and one of them changed this page's classification.
A receiver whose type is written out resolves even when the type is declared in another package as a GALA struct, while a receiver whose type is inferred from a call into a Go-declared function does not resolve at all, so `logs.Size()` reaches `go build` verbatim (`blocked_size_inferred_receiver`).
The transpiler reads a receiver's type from the `.gala` file's own text and will not read a Go sibling's signature.
`go_interop.SliceFrom(logs, 0).Size()` reaches the same length without naming the type, and the substitute allocates nothing (`pass_slice_from_size_len`).
What establishes that is a source line rather than a benchmark: the vendored helper is a one-line reslice at [`go_interop/types.go:116`](../server/third_party/gala/go_interop/types.go), whose own doc comment calls it `O(1)`.
A multi-value binding cannot be annotated, but that is a grammar shape rather than the only spelling, so this row is a workaround and not a boundary gap.
`go_interop` ships `MapLen` and `SliceCap` and no slice-length and no string-length helper, so a `string` receiver from a Go sibling has no zero-cost spelling and stays handwritten.
The lowering defect is filed upstream as #613.

### Resource cleanup without `defer`

`use x = acquire` is supported and lowers to `x := acquire` plus `defer x.Close()`.
It only accepts a single-value acquire, so `(T, error)` call sites must handle the error first and then `use` the value, as `pass_use_resource` does.
When the acquire already happened or the release is not `Close()`, use `resource.Using` or `resource.Bracket`, and a mutex uses `resource.WithLock`.
A GALA-declared resource type infers both type arguments, which is why upstream's own example calls `Using(Handle(...), (h) => ...)` with none written out, and `WithLock` infers either way.
When the resource's type comes from a handwritten Go sibling, inference binds the body parameter to `any` and the emitted Go does not build, so both type arguments are written out there (`blocked_resource_go_sibling_type`), and a partial list emits the transpiler's own type-parameter name as a Go type.
Filed as #618.
An earlier entry in this page claimed that omitting the result type argument strips the enclosing function's return type; it does not, and the enclosing signature is emitted unchanged in every variant.
Panic recovery and defers that mutate named return values stay handwritten.

### Panic versus Try

A recoverable failure uses `Try(goCall())`, which wraps a Go `(T, error)` call and flows as a value (`pass_try_recover`).
An unrecoverable invariant uses `go_builtins.Panic` in statement position (`pass_go_builtins_panic`).
The tail-position spelling `func f() int = Panic(...)` lowers to Go's void `panic(...)` in value position and fails to build (`blocked_panic_tail_position`), so keep the invariant as a statement with an early return.
`blocked_panic` pins the bare-builtin rejection.

### Slice ranges

Every slice expression is expressible: `xs[from:to]` maps to `go_interop.Slice(xs, from, to)`, the one-sided forms map to `SliceFrom`/`SliceTo`/`SliceTake`/`SliceDrop`, and `copy` maps to `SliceCopy`.
`pass_slice_ranges` pins all of them, and `blocked_slice_expression` pins the parse error; no slice expression needs a handwritten sibling.

### Go containers versus GALA collections

The container type decides, not the file style.
A Go `[]T` or `map[K]V` keeps the `go_interop` helpers: `SliceOf`/`SliceEmpty`/`SliceWithSize`/`SliceWithCapacity`, `SliceAppend`/`SliceAppendAll`, `MapEmpty`/`MapPut`/`MapDelete`, and `ToBytes` (`pass_go_interop_map_slice`).
A GALA `Array` or `HashMap` uses constructors and methods: `ArrayOf`/`EmptyArray`/`.Append`, and `EmptyHashMap`/`.Put`/`.Remove` (`pass_hashmap_array`).
`make` follows the same split, and the blocked literal probes pin the parse errors.

### Plain vars for constants

A `const` becomes a package-level `var`, or a `val` for a GALA-internal binding, and `pass_plain_var` pins the emitted plain Go var.
A name that must stay a Go compile-time constant, such as an exported `const` API or an array length, stays handwritten.

### The response name collision

When a `.gala` file names a type that an imported package also exports, the bare name in a **declared-type position** — a return type, a parameter type, a `var` annotation — resolves to the imported package, while a constructor position resolves to the local declaration.
`blocked_bare_name_type_gala_sibling` pins the substitution with a field that exists only on the local type, in the layout the issue was filed against: a sibling `.gala` declaration plus an import that exports the same name, and no handwritten Go at all.
The sibling's language is not what decides it, so `blocked_bare_name_type_position` pins the same substitution with a handwritten `.go` sibling instead, which is the layout this repository hit.
Only a declaration in the same `.gala` file resolves correctly, so the repo workaround is a handwritten constructor (`newResponse` in `slackbot/commands/utils.go`) that keeps the type out of the `.gala` file entirely (`pass_name_collision_workaround`).
`contested_bare_response_name` uses only the constructor position, which is why it transpiles and builds and why the earlier reading of this finding never reproduced.
Filed as #616.
`contested_bare_response_name` shows the bare `Response` literal resolving locally in an isolated corpus package, matching the PR #529 note that the collision did not reproduce standalone.

### Exported `val` unwrapping

`val ExportedAnswer = 99` emits `var ExportedAnswer = std.NewImmutable(99)`.
`pass_exported_val` has the runner write a Go `check.go` fixture that calls `.Get()`, so the probe proves both the emitted shape and the Go-side unwrap.
Keep `var` for values that cross the boundary.

### `go_interop` replacements

`MapEmpty`/`MapPut`/`MapDelete`/`MapLen`, `SliceOf`/`SliceFrom`/`SliceAppend`/`SliceCopy`, and `ToBytes`/`ToString` replace map literals, `make`, slicing, `append`, `copy`, and `[]byte(x)`.
`pass_go_interop_map_slice` and `pass_slice_ranges` pin them, including the comma-separated type arguments (`MapEmpty[string, int]()`).

## Probe corpus

The corpus lives at `server/scripts/20260923_gala_translation_probes/`.
It is a nested Go module whose `go.mod` replaces `martianoff/gala` with `../../third_party/gala`, so it compiles against exactly the vendored runtime.
Run it from the repository root:

```sh
server/scripts/20260923_gala_translation_probes/run.sh
```

The runner refuses to run unless `gala version` reports 0.84.1, because the expectations pin that compiler; `GALA_PROBES_ALLOW_ANY_VERSION=1` overrides the check.
It also requires a `go1.26` toolchain series, because the `build_fail` expectations embed Go compiler diagnostics; `GALA_PROBES_ALLOW_ANY_GO=1` overrides that check.
Each `probes/<name>/` directory holds a `main.gala` and an `expect` file.
The probe group table at the end of this section links every probe name to its directory under the corpus.
The four expectation kinds, and which one a new claim needs:

| Kind                  | Asserts on                             | Use it for                                             | Keys                                                                   |
| --------------------- | -------------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------- |
| `KIND=pass`           | program behaviour                      | a claim about what the program does                    | `RUN=yes` diffs stdout against `expected.out`                          |
| `KIND=transpile_fail` | a transpiler rejection                 | a claim that a construct is rejected at transpile time | `CODE` and `ERR` are checked against the diagnostic                    |
| `KIND=build_fail`     | a compiler rejection on the emitted Go | a claim that the emitted Go does not compile           | `ERR` is checked against the `go build` diagnostic                     |
| `KIND=emit`           | the text of the emitted Go             | a claim about the shape of the emitted Go              | repeatable `CONTAINS` and `ABSENT` literal substrings of `main.gen.go` |

A `KIND=emit` probe transpiles and then asserts on the text; it neither builds nor runs the program, because the claim is about codegen rather than behaviour.
`CONTAINS=<marker>` must appear in `main.gen.go` and `ABSENT=<marker>` must not; both keys are repeatable, so one probe can pin several markers, and the polarity lives in the key name, so a marker needs no escaping.
Pick the kind by the claim, not by convenience: a construct can be accepted with the wrong shape, so neither rejection kind carries a shape claim, and a wrapper the program never observes is invisible to an output assertion, so `KIND=pass` does not either.
A marker has to name a semantic thing, such as a wrapper constructor call, a synthesized interface or method, or a method call on a binding, and never whitespace, indentation, or a line break, because the emitted Go is formatted and carries `//line` directives naming the probe's own source.
On a failure the runner prints the numbered generated Go and, for a broken `ABSENT`, the matching lines with two lines of context; the full copy lands in `.logs/<name>.emit.txt`.

`KIND=emit` is coupled to the compiler release more tightly than any other kind, because it pins codegen instead of behaviour, so a GALA bump is expected to fail these probes by design.
Re-baseline them by running the corpus with `GALA_PROBES_ALLOW_ANY_VERSION=1` and reading the numbered generated Go in the failure output: if the new shape is intended, update the marker; if it is not, the finding belongs in this page and, if it blocks a construct, in a `GAP-n` row.

Generated Go files (`main.gen.go` and `sibling.gen.go`), runner-written Go fixtures (`probes/*/helper.go`, `probes/*/check.go`, `probes/*/types.go`, and `fixtures/collide/response.go`), logs, and binaries are gitignored by explicit path, so a future handwritten Go fixture is not silently ignored, and only `.gala` sources, `expect` files, `expected.out` files, `go.mod`, `.gitignore`, `run.sh`, `audit.sh`, and the `inventory/` Go sources and tests are committed.
Go fixtures that exist only to reproduce a mixed-package case are written by the runner, not committed.
`audit.sh` is read-only and needs no GALA or Go toolchain: it checks the probe directories, rejects orphan probes and unresolved roster links, requires every genuine-gap entry to name a failing non-contested probe, checks the class-to-`GAP-n` mapping against [`../server/GALA.md`](../server/GALA.md), and gates the [Mechanical rewrites](#mechanical-rewrites) catalog against the construct roster in both directions.
It classifies probe kinds rather than inheriting the `KIND=pass` rule, because a blocker has to fail for the construct it names: `KIND=pass` asserts behaviour, and a `KIND=emit` probe carrying a `CONTAINS` marker pins a shape that is there rather than a shape that is missing, so neither can back a gap claim, while a `KIND=emit` probe whose markers are all `ABSENT` can, because a construct is blocked exactly when the thing it needs is not emitted.
Both the class check and the catalog check read the construct roster section of this page, so a same-shaped table in another section cannot influence either of them.
`inventory/main.go -check` re-derives the [Inventory](#inventory) counts; run both alongside `run.sh`.

The transpiler emits no documentation comments, at any position and for either comment syntax.
That is an output limitation rather than a Go construct, and it has two prices: an exported declaration's godoc is gone, and a `swag` annotation written in a `.gala` source is gone from the generated `.go`, so `swag init` drops the endpoint from the OpenAPI document.
A package comment is recoverable from a handwritten `doc.go`, as [`../server/GALA.md`](../server/GALA.md) records; a declaration comment and an annotation are not, because a comment has to sit immediately above its declaration and the only spelling is a bodiless re-declaration, which is a Go error.
Filed upstream as #619.

## Mechanical rewrites

One row per rule rather than per construct family, so a rewriter can apply a substitution without joining cells across the roster table.
Every row pairs a Go spelling with the GALA spelling that replaces it, carries the condition that selects the branch, names the probe that pins it, and lists the construct families it covers.
The `go_interop` and `resource` spellings need `import "martianoff/gala/go_interop"` and `import "martianoff/gala/resource"`; the qualified prefix is what the committed twins use.
A family may appear on more than one row when the decision rule has genuinely different branches, and every branch names its own probe.
`audit.sh` gates this section against the [Construct roster](#construct-roster) in both directions: a row that names a probe the corpus does not have, a substitutable family with no row, a row that claims a family the roster does not classify as substituted, and a family missing from the no-rewrite index below all fail it.

## When to revisit

Bump the CLI and the vendored runtime together, then run the corpus with `GALA_PROBES_ALLOW_ANY_VERSION=1` and re-baseline from the failures: the seven `delta_*` probes, the eight `emit_*` probes, and `blocked_defined_type_receiver` are the ones that move when a release changes a probed behavior, and any new `GALA-Exxxx` code needs a roster row and, if it blocks a construct, a `GAP-n` entry.
The `emit_*` probes are the ones expected to move, because they pin codegen rather than behaviour, so a compiler bump is meant to make them fail.
Re-baseline each of them by reading the numbered generated Go in the failure output: when the new shape is intended, update the marker to the new semantic name; when it is not, the finding belongs in this page and, if it blocks a construct, in a `GAP-n` row.
Re-vendor the runtime by following the update procedure in [`../server/GALA.md`](../server/GALA.md), so the compiler and the vendored stdlib snapshot never drift apart.
Regenerate the committed twins with the new version only after reviewing the diff, and re-run the server tests; at 0.84.1 the regeneration was byte-identical, so a future version that changes codegen should be read as a deliberate upstream change rather than expected noise.
A Go toolchain bump can change the `go build` diagnostics the `build_fail` probes assert; update those expectations and `EXPECTED_GO_SERIES` in `run.sh` together.
Run `server/scripts/20260923_gala_translation_probes/audit.sh` after any roster, corpus, or `server/GALA.md` edit, and `go run ./inventory -check` from the corpus directory after any `server/` change that touches an inventoried construct; both are toolchain-free and fail on the drift they check.
Keep this page, [`../server/GALA.md`](../server/GALA.md), and the probe corpus in sync: a verdict or gap-class change is a probe and roster update in all three.
