# GALA Loop

This is the continuation loop for the server's GALA twins.
It reads state from [`server/GALA.md`](../../../server/GALA.md) and translation knowledge from [`gala-from-go`](../gala-from-go/SKILL.md); it restates neither.
Run it one iteration at a time: bump first when the compiler moved, then translate at most one candidate.

## Preconditions

- Work from `nix develop`, which provides the flake-locked `gala` compiler and Go toolchain.
- Record the provenance before touching anything: `gala version`, `which gala`, `jq -r '.nodes.gala.locked.rev' flake.lock`, and `cat server/GALA_COMPILER`.
- Confirm every twin-related path is committed, so a later failure is attributable to this iteration: both halves of each existing twin, the ledger, and the skill files are in commits rather than in the working tree.
  Known unrelated edits are exempt and are left alone; at least `backlog/backlog.md` carries a permanent unrelated modification, so a globally clean `git status` is neither required nor an exit condition.
- Read `server/GALA.md` for the twin registry, the open findings, the upstream report index, and the cursor.
- Read the adopted runtime module and version from `server/go.mod`: a twin's generated Go may import `go.gala.fyi/stdlib/...` from the pinned module, and `martianoff/gala` is never allowed.
- Load [`gala-from-go`](../gala-from-go/SKILL.md), and read the construct row for every construct the candidate uses before writing a line of GALA.

## Step 0: Bump when the rev moved

A bump is required when the flake rev differs from the flake rev recorded in `server/GALA_COMPILER`.
It is its own iteration: do not translate in the same iteration.

1. Run the bump and re-baseline procedure in `server/GALA.md`.
2. Run `server/scripts/gala/verify.sh --write`.
3. Review the per-twin diff.
   An expected codegen change is kept and recorded; a regression is a finding and stops the bump rather than being papered over.
4. Run `go build ./...` in `server/` and the canonical backend test sequence in [`server/README.md`](../../../server/README.md).
5. Record the new provenance in `server/GALA_COMPILER`, and note every shape change the bump produced.

Never translate across a rev mismatch, because a twin generated by one compiler is not reproducible under another; a bump is always its own re-baseline iteration.

## One iteration

The cursor in `server/GALA.md` is ordered; take its next workable entry and re-check its constructs on the pinned compiler before writing GALA, because a cursor entry is a candidate and not a verdict.
An entry already recorded as blocked needs no re-probe while its finding carries a committed probe last re-verified on the current compiler rev, because that probe's recorded result still speaks for this rev.
Re-run the probe only when the flake rev moves or the finding's upstream state changes, and update the cursor entry with the rev the re-verification was on.

1. Read the ledger's findings for the candidate's package, and the report index for any upstream item it names.
2. Pre-triage the candidate with `gala-from-go`'s triage: run each construct row's own check, and treat a ledger finding recorded as fixed on this rev as a workaround rather than a wall.
3. Follow `gala-from-go`'s mechanical pass and verify sections in order, transpiling to a scratch path first so a parse error costs nothing.
   Every transpile carries `--stdlib-module go.gala.fyi/stdlib`, and the real twin is written from the package directory: `cd server/<pkg> && gala transpile --stdlib-module go.gala.fyi/stdlib -i <name>.gala -o <name>.go`.
4. Register the twin: add its row (source, generated file, handwritten sibling, runtime status) to the twin registry in `server/GALA.md` and remove it from the cursor.
5. Run `server/scripts/gala/verify.sh`, then `go build ./...` in `server/` and the canonical backend test sequence in `server/README.md`.
   Read the generated import block before committing: a runtime import must be the `go.gala.fyi/stdlib/...` module pinned in `server/go.mod`, and `martianoff/gala` fails `verify.sh`.
   A `verify.sh` failure that a second run does not reproduce, or drift in a twin this iteration did not touch, is the stale `server/.gala/` cache signal recorded in the ledger rather than real drift: delete `server/.gala/` and re-run before investigating.
6. Record the iteration in the ledger when it changes a finding: a workaround becomes a row in the open findings table, and a closed finding is deleted with a note in the report index.
7. Finalize: commit the iteration as one change — both halves of the landed twin, the ledger update, and the task notes — and leave the unrelated edits named in the preconditions uncommitted and unmodified.

A completed twin whose registry row is missing is not finished, because the next iteration reads the registry as the list of what exists; the same holds when its two halves are uncommitted, because the next iteration reads git for what landed.

### Workaround blockers

When a construct has a substitute, take the substitution from `gala-from-go` and continue; a `workaround` or `answered` row is not a reason to stop.
Record the substitution in the ledger's open findings when it affects a commit decision, and add its row to `gala-from-go` when no existing row covers it, so the next iteration reads the spelling from the reference rather than re-deriving it.

### No-workaround blockers

When a construct is genuinely blocked and no substitute preserves the Go-facing behavior:

1. Classify it with [`references/gaps.md`](../gala-from-go/references/gaps.md), and do not file a substitute as a gap.
2. Add a committed repro at `server/scripts/gala/probes/<slug>/` containing `main.gala` and `notes.md`.
   The probe gets its own directory because the transpiler loads every `.gala` file of the input directory, so two probes sharing a directory would transpile together.
   The notes record the exact invocation, the observed diagnostic, the expected Go shape, the compiler rev, and the date; generated files go to a scratch path, not the probe directory.
3. Search the upstream tracker for an existing report on the construct.
4. Create a Backlog task containing the filled report template from `references/gaps.md`.
   The loop does not file or comment on upstream issues itself; the Backlog task is the handoff.
5. Add the finding to the ledger's open findings table with its class, workaround or none, upstream link, and the probe path, and leave the candidate in the cursor.
   When working the blocker derived a construct substitution that no `gala-from-go` row covers, add that row to the reference in addition to the ledger finding, because the reference is where the next iteration reads substitutions.
   Delete the probe and the row when the blocker closes.

## Stop conditions

Stop and report instead of proceeding when any condition in [`Stop And Report`](../gala-from-go/SKILL.md#stop-and-report) holds, and obey its `Never` list.
The project additions are:

- Never hand-edit a generated twin; the next transpile discards the edit.
- Never transpile from the repository root, because the emitted `//line` directives name the path the transpiler was given.
- Never reshape a Go-facing signature, struct tag, or wire format to make the transpiler accept a file.
- Never relax a test to accommodate a translation.
- Never commit a twin whose generated Go imports `martianoff/gala`; a runtime import must be the `go.gala.fyi/stdlib/...` module pinned in `server/go.mod`, and a twin whose Go-facing surface the runtime shapes would change uses a handwritten sibling in the same package (GO_INTEROP.MD Part 3) or stays handwritten.
- Never mix a compiler bump with a translation, because the bump and the iteration have separate evidence.
